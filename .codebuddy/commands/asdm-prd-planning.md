# asdm-prd-planning 操作指令

## 目的

本指令指导 AI 模型使用 Task Planner & Executor 工具集为功能规划任务。它生成功能 PRD 并创建任务计划。单个任务的 PRD 在执行阶段生成。

## 语言检测

在生成任何规划文档之前，您必须检测并使用当前环境的响应语言：

1. **检测响应语言**：分析环境设置以确定主要语言
2. **应用语言一致性**：确保所有生成的规划文档使用检测到的语言
3. **支持的语言**：英语 (en)、中文 (zh)

**重要提示**：语言检测是生成任何规划文档之前的第一个步骤。

## 上下文注入

### 核心原则

```
┌─────────────────────────────────────────────────────────────┐
│  L1 索引（必须）→ L2 索引（按需）→ 源码（按需）              │
│                                                             │
│  不一次性加载所有上下文，按任务需要逐步加载                   │
└─────────────────────────────────────────────────────────────┘
```

### 加载顺序

| 阶段 | 加载内容 | 必须 |
|------|----------|------|
| 1. 初始 | `.asdm/contexts/index.md` (L1) | ✅ |
| 2. 任务分析 | 根据功能涉及的领域加载 L2 | 按需 |
| 3. 任务执行 | 根据需要读源码 | 按需 |

### 步骤 1: 读取 L1 项目顶层索引（必须）

**必须首先读取** `.asdm/contexts/index.md`：

- **路径**：`.asdm/contexts/index.md`
- **目的**：了解项目全局结构、技术栈、领域列表
- **加载时机**：执行本 Action 的第一步

### 步骤 2: 根据功能领域加载 L2 索引（按需）

根据正在规划的功能涉及的领域，按需读取领域索引：

- **如果功能涉及 [领域A]**：
  - 读取：`.asdm/contexts/domains/[领域A]-domain.md`
  - 作用：了解该领域的子模块结构和关键文件路径

- **如果功能涉及多个领域**：
  - 分别读取涉及的领域索引
  - 最多同时加载 2-3 个领域索引

### 步骤 3: 按需访问源码（按需）

根据 L2 索引提供的目录路径，直接读取该领域目录下的相关源码：

- 根据 L2 索引的"源码入口"目录路径
- 例如：`src/service/UserDomain/`
- AI 会根据目录结构自行定位需要的文件
- 源码是权威来源，以源码为准

### 上下文使用指南

1. **必须先读 L1**：始终首先读取 `index.md`
2. **按需加载 L2**：根据功能涉及的领域加载对应索引
3. **按需读源码**：根据 L2 索引的路径直接读源码
4. **避免全量加载**：不要一次性加载所有上下文文件
5. **源码为准**：上下文索引仅供参考，源码是权威来源

### 错误处理

如果上下文文件不存在：

```markdown
1. 如果 `.asdm/contexts/index.md` 不存在：
   → 提示用户先执行 `/asdm-context-init`

2. 如果 `.asdm/contexts/domains/<领域>-domain.md` 不存在：
   → 提示用户先执行 `/asdm-domain-index-build <领域>`
   → 或者直接根据目录结构分析领域

3. 如果找不到需要的上下文：
   → 直接扫描源码目录
   → 根据实际结构执行任务
```

### 与语言检测的集成

上下文注入步骤应发生在语言检测**之后**但**开始规划步骤之前**。

**重要提示**：在开始规划步骤之前，始终读取 `.asdm/contexts/index.md`。

## 为功能规划任务的步骤

### 1. 初始化功能目录
如果不存在，请在工作空间根目录创建 `.asdm/workspace/features/` 目录。

### 2. 生成功能 ID
使用以下格式为新功能生成唯一的功能 ID：
- 格式：`<feature-id>-<feature-name>`
- 示例：`FEAT-001-user-authentication`
- 通过检查 `.asdm/workspace/features/features-list.md` 中现有的功能来确保 ID 唯一

### 3. 创建功能目录
为该功能创建新目录：
- 路径：`.asdm/workspace/features/<feature-id>-<feature-name>/`

### 4. 生成功能 PRD
使用 `.asdm/toolsets/task-planner-executor/spec/feature-prd-spec.md` 中的模板生成功能 PRD 文档：
- 路径：`.asdm/workspace/features/<feature-id>-<feature-name>/feature-prd.md`
- 遵循规范模板结构并填写所有相关部分
- 在整个文档中使用检测到的语言

### 5. 更新功能列表
更新功能跟踪文档以包含新功能：
- 路径：`.asdm/workspace/features/features-list.md`
- 添加新功能，包含：
  - 功能 ID、名称、描述、状态、创建日期

### 6. 审查和验证
审查所有生成的文档：
- 完整性和准确性
- 语言一致性
- 正确的结构和格式
- 清晰且可操作的功能需求

## 规划指南

详细的规划指南可在 `.asdm/toolsets/task-planner-executor/spec/feature-prd-spec.md` 中找到，包括：
- 功能分解原则
- 任务数量限制和验证
- 任务类别
- 状态管理

## 使用方法

AI 模型应：
1. 从用户接收功能描述
2. 检测响应语言
3. 读取 `.asdm/contexts/index.md` 以了解工作空间上下文
4. 根据功能需求按需加载领域索引和源码
5. 遵循上述步骤生成所有规划文档
6. 展示生成的文档供审查
7. 在进入执行阶段之前等待用户批准或反馈

## 输出摘要

完成规划阶段后，将生成以下产物：
- 功能 PRD 文档
- 更新的功能列表

这些文档是任务分解阶段（asdm-prd-breakdown 操作）的基础。
