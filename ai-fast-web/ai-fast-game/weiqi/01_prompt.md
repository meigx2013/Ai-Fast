# 开发围棋游戏完整版

角色：你是一名资深前端工程师，擅长写简洁、可维护的小游戏代码，熟悉棋盘类游戏的交互与算法设计。

任务：开发一款可在浏览器中游玩的双人对弈围棋游戏，输出为单个 HTML 文件（HTML/CSS/JS 内联），双击即可在浏览器运行，不依赖任何外部库或网络资源。

## 核心玩法

1. 在 19×19（可配置为 9×9 / 13×13）网格棋盘上，黑白双方轮流落子，黑棋先行。
2. 实现围棋基本规则：
   - 落子后若导致对方某块棋子无气（无相邻空点），则提掉该块棋子。
   - 禁止自杀：若落子后自身棋子块无气且未提掉对方棋子，该落子非法。
   - 禁止劫争：落子不能立即还原上一手造成的棋盘局面（简单劫规则即可，无需超级劫）。
3. 提供「虚手（Pass）」操作，双方连续两次虚手则对局结束，进入数子结算。
4. 简单数子：统计双方活子数 + 所占区域（可采用简易的「数子法」，无需精确处理复杂死活，但需给出合理的终局判定说明）。

## 操作与交互

1. 鼠标点击交叉点落子，落子前显示半透明预览棋子（悬停提示）。
2. 提供「虚手」「悔棋」「重新开始」按钮。
3. 悔棋至少支持撤销一步（建议支持回退到任意历史局面）。
4. 非法落子（自杀、劫争、非空点）需给出友好提示，且不改变当前状态。
5. 显示当前执棋方（黑/白）、双方提子数、手数。

## 视觉要求

1. 棋盘用 Canvas 实现，网格线清晰，交叉点明确，棋盘带木纹质感（用渐变或纯色模拟即可）。
2. 棋子用圆形绘制，黑白分明，带简单高光/阴影增强立体感。
3. 最后一手落子位置用标记（如小圆点或方块）高亮显示。
4. 页面顶部显示当前执棋方、黑方提子数、白方提子数、手数。

## 代码质量要求

1. 逻辑分层清晰：初始化、输入处理、落子校验（气计算 / 提子 / 劫争判断）、状态更新、渲染分离，关键函数加注释。
2. 气计算与提子逻辑需封装为独立函数（如 `getGroup`、`countLiberties`、`removeDeadGroup`）。
3. 变量命名语义化，避免全局变量污染（可用模块化 IIFE 或简单对象封装）。
4. 处理边界情况：棋盘边缘落子、游戏结束后忽略落子输入、悔棋后劫争状态正确恢复。
5. 棋盘尺寸可通过常量配置，切换尺寸时重置对局。

## 输出

1. 输出完整的代码，保存到 `weiqi` 目录下。
