# 弈境 v2 · 人与系统对弈改造总体方案与分任务执行提示词

> 本方案承接 `03_prompt.md` 已交付的人机对弈版本（FastAPI 后端 + LLM 优先 + 启发式兜底、单文件 Canvas 前端、133 个自动化测试），将三项改造需求拆为 **14 个有序任务**。每个任务包含**具体目标**、**执行流程**（可直接作为编码 AI 的任务提示词逐条执行）、**交付物**与**验证标准**。任务拆分遵循"一个任务只做一类事、只改一类文件、有独立可跑的自验证"的颗粒度原则。

## 改造需求与总体方案

### 需求解读

| # | 需求 | 方案要点 |
|---|---|---|
| 1 | 人与 AI 对弈 → 人与系统对弈 | 彻底移除 DeepSeek/LLM 专用链路（密钥、模型超时、模型重试、模型降级），对手重构为后端常驻的**级位对弈引擎系统**；普通 HTTP 超时/失败重试与规则安全兜底不属于 LLM 链路，应按既有前端契约保留；接口更名 `POST /api/system-move`；健康检查改为引擎信息；前端文案与状态面板全面改为"系统" |
| 2 | 增加终局判定和胜负计算 | ① 终局判定：保留双方连续两次 Pass 与无合法点时当前方 Pass 的规则，新增**级位化主动 Pass**；只有连续两次 Pass 才进入终局；② 胜负计算：新增结算服务——死子判定（系统建议 + 用户点击修正两阶段）、中国数子法、贴目 3¾ 子、净胜子数；新端点 `POST /api/score`；前端终局结算交互 |
| 3 | 10 级～1 级真实水平引擎 | 后端重建专门对弈引擎：`analyzer/` 分析模块库承载各级别**思维方式**，`levels.py` 级位能力档案（模块开关 + 精度 + 误判率 + 视野 + 落子习惯 + 搜索深度 + 候选策略）承载级位差异，`decision.py`（候选生成→视野过滤→模块评分→搜索验证→误判注入→习惯扰动→Pass 判定）+ `habits.py` 负责级位化决策 |

### "真实水平"的可验收定义（需求 3 的判定口径）

本方案将"真实水平"落地为**可复现的级位行为仿真与内部相对棋力**，不能只靠参数表声称，必须由**可复现的算法差异 + 可量化的独立行为测试 + 自对弈强度矩阵**三者共同证明。自对弈只能证明本引擎内部级位的相对强弱，不能证明其与真实人类 10 级～1 级一一对应；若需宣称绝对人类级位，必须另做人类棋手或外部参考引擎校准。本校准不在当前 14 个任务范围内，交付文档必须明确标注"未经人类级位校准"，不得把内部胜率包装成真实棋力认证。

1. **算法差异**：每级由 `LevelProfile` 的六维参数（`vision` / `modules` / `accuracy` / `mistake_rates` / `habit_weights` / `pass_threshold`）加两个新维度 **`search_depth`（局部搜索深度）** 与 **`candidate_policy`（候选生成策略）** 唯一确定；级间参数单调（视野不减、误判率不增、搜索深度不减、模块集合只增不减）。
2. **行为差异**：每级至少一条固定种子行为断言（见任务 3a～5b 自验证），覆盖"会什么 / 看不见什么 / 犯什么错"。战术测试使用带独立标准答案的固定盘面，不得以被测引擎自身评分作为"正确答案"。
3. **强度差异（以配对自对弈和统计证据验收，不以前置数值凑结论）**：
   - **排序目标**：数字越小棋力越强。9 路全量 `45` 个无序级位组合为主矩阵，对任意 `i<j`，以高级位得分率 `p(i,j)=(高级位胜局数+0.5×和局数)/有效总局数` 检验 `p(i,j)>50%`；相邻级位允许差距较小，**不统一预设 `≥52%`**。跨档组合（`j-i≥3`）的平均得分率应高于相邻组合，`1 vs 10` 作为远端锚点，其最低可接受得分率由先导实验确定，**不再先验写死 `≥75%`**。
   - **实验设计**：固定引擎版本、参数、棋盘尺寸、手数上限与结算规则；每个组合使用同一组预登记种子和初始局面交换黑白各赛一局，避免先后手与贴目偏差。每对至少 `100` 局（`50` 个种子对），并根据 T5c 先导实验的功效分析增加样本量（全矩阵族系错误率 `FWER=0.05`、单侧检验、检验效能 `≥80%`；样本量估算须考虑 Holm 校正后的显著性水平，而非直接把未校正的 `α=0.05` 当作每对门槛）；同时报告黑/白分项结果，不能只报告合并值。
   - **统计判定**：报告每组对局的局数、胜/负/和、得分率及置信区间；以颜色互换的种子对为重采样单位计算聚类 bootstrap 区间和单侧 `p` 值，再用 Holm 法控制全矩阵 `FWER=0.05`。验收要求每组点估计均 `>50%` 且校正后 `p<0.05`；样本不足导致的“不显著”不得解释为强度相同，也不得用单次点估计代替结论。达到手数上限、异常退出等无效局的识别与剔除规则必须预登记，并按种子对保留或剔除，禁止只剔除不利的一侧。Elo/Bradley–Terry 等评级仅作全局趋势辅助，不能替代逐对结果。
   - **校准与防过拟合**：T5c 的先导数据只用于估计方差、样本量与候选阈值；T8 在独立验证前冻结代码、参数、种子清单、样本量和阈值，再用未参与调参的对局验收。不得采用“实测值减 5 个百分点”设定阈值，不得通过删局、换种子、反复调参后复用同一批数据或事后降低阈值制造通过结果。

### 级位思维方式模型（需求 3 的引擎设计基线）

真实级位棋手的思维方式与落子习惯，按 10 级→1 级建模如下（实现时以此表为级位档案 `levels.py` v2 的参数来源，并允许按实测微调、但级间单调性不得破坏）：

| 级位 | 思维方式特征（会什么） | 视野范围 | 典型落子习惯 | 典型错误（误判注入） |
|---|---|---|---|---|
| 10 级 | 只算眼前一手：看到能提子就提，自己被叫吃时多数时候会逃；无布局/围空/死活概念 | 上一手 ±2 格与己方被叫吃块 | 开局随手（星位附近或任意三线点）、贴身缠绕近战 | 约 40% 概率忽略被叫吃；约 30% 送吃（落子后自身仅 1 气）；在对方厚势中送死 |
| 9 级 | 吃子熟练；有围空意识但效率低（沿一、二线爬行）；知道逃子方向 | 上一手 ±3 格 | 开始走三线四线 | 约 25% 忽略叫吃；无理侵入对方阵势 |
| 8 级 | 对杀气数计算稳定；开局会占角（星位/三三）；懂得简单逃子与弃子 | 半盘 | 开局优先占角，占角后常不守不拆 | 约 20% 忽略叫吃；常弃已占区域 |
| 7 级 | 布局概念形成：空角→挂角→拆边顺序；理解连接与分断；简单死活（直三死/曲四活等粗浅）；征子只看 1~2 步 | 全盘粗略 | 角→边的行棋顺序 | 约 15% 忽略叫吃；布局方向偶尔错误 |
| 6 级 | 布局成形（星小目 + 拆边合理）；对杀可靠；基础手筋（双打吃/关门吃）；常见死活棋形（板六等）；连接分断明确 | 全盘 | 星小目开局 + 按序拆边 | 约 10% 忽略叫吃；不识定式；官子无序 |
| 5 级 | 死活棋形熟练（直三/曲三/丁四/刀把五/板六/盘角曲四）；手筋掌握扑/接不归；征子可读约 5 步；候选选择集中 | 全盘 | 有明确攻防目标的选点 | 约 7% 忽略叫吃；打入时机差 |
| 4 级 | 基础定式记忆（常见角部定式按型走）；手筋熟练；局部可计算 3~5 步 | 全盘 + 局部深算 | 挂角后按定式应手 | 约 5% 失误；定式后行棋方向模糊 |
| 3 级 | 布局选点合理（大场判断入门）；中盘战术：攻击弱棋/切断联络；把握打入与侵消时机；有先手官子概念 | 全盘 + 形势粗判 | 打入/攻击/先手收官 | 约 4% 失误 |
| 2 级 | 大场与急所优先级判断可靠；形势判断雏形（目数估算）；收官有序（先手官子→大后手） | 全盘 + 形势判断 | 收官有序推进 | 约 2% 失误 |
| 1 级 | 综合实战：布局—中盘—官子完整框架；全局平衡（实地与外势）；形势判断可靠；领先时安全运转、落后时拼搏；计算深度最深 | 全盘 | 领先时稳健收官、落后时主动拼搏 | ≤1% 失误（近似无低级错误） |

### 级位引擎算法基线（各级别算法差异）

引擎统一管道（`decision.py`）：

```
候选生成(candidate_policy) → 视野过滤(vision) → 模块评分融合(modules+weights)
→ 局部搜索验证(search_depth) → 误判注入(mistake_rates) → 习惯扰动(habit_weights)
→ 合法性双保险 → Pass 判定(pass_threshold)
```

| 级位 | 候选生成策略 | 搜索深度 | 评分融合方式 | 关键算法差异（真实水平来源） |
|---|---|---|---|---|
| 10 级 | 仅上一手邻域 + 己方被叫吃块邻点，随机采样 ≤20 点 | 0（不算） | 单模块贪心（capture 优先，其余忽略） | 无搜索、无形势判断；`ignore_atari`≈40%、`blunder_rate`≈30% 概率注入 |
| 9 级 | 上一手 ±3 格邻域，≤30 点 | 0 | capture + opening 线性加权 | 仍无搜索；误判率降档；开始偏好三/四线 |
| 8 级 | 半盘按距离衰减采样，≤40 点 | 1 ply（提子/逃子后气数复算） | 多模块加权，opening 的占角子能力权重高 | 首次出现"落子后一手验证"，占角习惯固化 |
| 7 级 | 全盘粗采样，≤60 点 | 1 ply | 加权 + 简单连接/分断项 | 全盘视野但无深算；布局顺序（角→边）出现 |
| 6 级 | 全盘候选，≤80 点 | 2 ply（对杀/死活局部） | 加权 + life_death 基础棋形查表 | 首次接入棋形库（直三/板六）；双打吃/关门吃 |
| 5 级 | 全盘候选 + 局部加密，≤100 点 | 3 ply | 加权 + tesuji + ladder（专项上限 5 ply） | 手筋全开、征子可读；候选选择集中 |
| 4 级 | 全盘 + 角部定式库匹配，≤120 点 | 3～5 ply | 加权 + joseki 序列匹配 | 定式记忆生效；局部计算 3~5 ply |
| 3 级 | 全盘 + 大场/急所分类，≤150 点 | 5 ply | 加权 + middle（切断/攻击/打入）+ endgame 先手 | 中盘战术与先手官子概念 |
| 2 级 | 全盘 + 形势反馈调权，≤180 点 | 5～7 ply | 加权 + territory 形势判断 + endgame 大小排序 | 收官有序（先手→大后手） |
| 1 级 | 全盘 + 全局平衡评估，≤200 点 | 7～9 ply（对杀/死活加强） | 全模块 + 形势反馈（领先稳健/落后拼搏） | 全局平衡与安全运转；误判 ≤1% |

### 级位统一参数维度（`LevelProfile` v2 字段）

每级一组参数，在 `levels.py` v2 中固化为 `LevelProfile` 字段。实现时须使用明确的 dataclass/类型注解和固定键名，禁止把未约定键塞进无约束字典：

| 字段 | 建议类型 | 语义与约束 |
|---|---|---|
| `vision` | 字符串枚举 | `last_move_2` / `last_move_3` / `half_board` / `full_board` 等固定标识；定义距离采用曼哈顿距离还是切比雪夫距离后全项目一致，本文“±N 格”统一指**切比雪夫距离 ≤N** |
| `modules` | `frozenset[str]` 或等效只读集合 | 仅存放 `capture`、`opening` 等顶层模块名；子能力用明确配置字段控制，不使用 `"opening.corner"` 这类未注册伪模块名 |
| `accuracy` | 专用结构化类型 | 至少含 `liberty`（0～1）、`ladder_steps`（非负整数）、`territory`（0～1）；概率与步数不得混用单位 |
| `mistake_rates` | 专用结构化类型 | 至少含 `ignore_atari`、`blunder_rate`，均为 0～1；每一次抽样的时机和对象固定，避免重复抽样导致实际频率漂移 |
| `habit_weights` | 专用结构化类型 | 贴身度、开局目标点偏好等固定键；评分权重与概率分开命名 |
| `pass_threshold` | 有限浮点数 | 与融合后的候选价值使用同一量纲；低级位高阈值表示几乎不主动 Pass，但不能覆盖合法性强检和必应手 |
| `search_depth` | 非负整数 | 局部搜索最大 **ply**（一方落一手计 1 ply），0=不搜索；不是“双方回合数”，也不等同于征子专用 `ladder_steps` |
| `candidate_policy` | 字符串枚举 | 邻域采样/半盘衰减/全盘/全盘+定式匹配/全盘+全局评估等固定标识 |

级间单调性由 `test_levels.py` 断言：`vision` 覆盖范围不减、各类 `mistake_rates` 不增、`search_depth` 不减、`modules` 集合只增不减。过渡级位也必须满足这些不变量；若某阶段无法断言全部字段，应明确列出暂未启用字段及启用任务，不能用“部分通过”代替最终通过。

关键不变量（所有级位都必须遵守）：

1. **合法性优先**：落子永远合法；决策返回非法候选时继续检查后续候选，无可用候选才进入兜底，不允许把非法坐标直接交给前端。
2. **可感知提子优先**：视野内且被当前级位启用模块识别的直接提子机会不得被习惯扰动或误判注入主动放弃；视野外机会不要求感知。该口径与低级位“看不见远处提子”的测试一致，不再声称“全盘任何提子机会都不放过”。
3. **确定性兜底**：引擎异常或无合法有效候选时，按从上到下、从左到右的行优先顺序选择首个合法点；仍无合法点才返回 `"pass"`。异常须记录服务端日志，但响应不泄露堆栈。
4. **可复现随机性**：所有随机选择只使用调用方注入的 `rng`，禁止模块内调用全局 `random`、当前时间或机器相关哈希。相同棋局上下文、级位、玩家颜色、引擎版本与种子必须得到相同 `move` 和模块标签；`elapsedMs` 不参与确定性比较。
5. **性能不改变结果**：搜索由深度、候选上限和固定节点预算约束；运行耗时只用于监控，不得因不同机器的墙钟超时改变固定种子下的选点。

### 终局与胜负计算规则

1. **Pass 来源有三种，终局条件只有一个**：
   - 玩家或系统主动选择 Pass；
   - 当前行动方无合法落点时返回/执行 Pass，而不是立即终局；
   - **级位化主动 Pass**（新增）：轮到系统时，若按级位启用的全部分析模块给出的最高候选价值低于该级位的 `pass_threshold`，系统可以主动 Pass。10~8 级阈值极高，几乎不主动 Pass；3~1 级正常收官后主动 Pass。
   - 只有双方**连续两次 Pass** 才进入死子确认与结算。单次 Pass 后另一方仍可落子；一旦落子，`consecutivePasses` 归零。若仍有直接提子、逃叫吃等当前级位可感知的必应手，不得因低分阈值提前 Pass。自对弈达到手数上限属于异常终止，不算正常终局或有效胜局。
2. **死子判定算法**（工程近似，两阶段）：
   - 先识别具备两只分离真眼的棋块并建议保留；真眼的局部启发式定义须在测试中固定，不能把假眼当作真眼；
   - 气数 ≤1、被对方完全包围且不满足活棋条件的棋块 → 建议死子，不称“必死”；
   - 被对方完全包围、气 ≤2 且无两眼的其他棋块 → 建议死子；
   - 其余中间态（气 ≥3 无两眼、疑似双活/劫活等）→ 不强制判定，交由用户在结算前点击修正。该算法不保证复杂死活、双活和循环劫的自动结论正确，用户确认结果才是本次结算输入。
3. **胜负计算**：清除用户确认的死子 → 数子（活子 + 独享空）→ 黑方减贴目 → 输出黑方视角净胜子数、胜负方及绝对差值摘要。

## 范围边界与风险

- **非目标**：超级劫（positional superko）、复杂死活的精确自动判定（以"建议 + 用户修正"两阶段规避）、让子、贴目自定义规则、账号系统、联网对战。

- **强度阈值的校准与多重比较风险**：T5c 先导数据只用于估计样本量和提出候选阈值，T8 必须在独立验证前冻结协议。若结果不显著，先区分“功效不足”与“真实效应不足”，不得在同一验证集上反复追加对局直到显著；确需扩样时使用新的预登记样本并采用相应序贯校正，调参后则重新独立验证。最终仍未达标时应修复引擎或如实披露级位区分度限制，不得事后降低阈值、删除 inversion（强弱倒挂）组合或只挑选有利结果。
- **接口更名无兼容层**：`/api/ai-move` 直接移除（同仓库前后端同步更新，无外部消费者）；T2b 完成后旧路径 404 属预期。
- **性能边界**：T5b 后与 T8 使用同一组固定的 19 路开局/中盘/官子盘面（每阶段至少 10 个）实测，报告各级位 `elapsedMs` 的样本数、P50/P95/最大值；以 **P95 ≤2 秒**为性能门槛。超限时应调整固定候选上限、节点预算或预筛算法，并重新跑确定性与强度验证；不得在运行中按墙钟时间动态截断搜索，避免相同种子因机器性能不同而选出不同棋。
