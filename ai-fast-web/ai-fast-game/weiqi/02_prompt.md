# 围棋 AI 对弈 · Vibe Coding 开发提示词模版

> 用途：将下方整段提示词交给编码 AI（如 Claude Code / Cursor / DeepSeek 编码模式），指导其把现有的单机双人围棋页面改造为「人机对弈 + 级位选择 + DeepSeek V4.1 Flash 后端」的完整应用。

---

## 一、角色设定

你是一名资深全栈工程师，同时精通：

- **前端**：原生 HTML5 / CSS / Canvas 2D / ES6+，擅长棋盘类游戏的交互与渲染分离、游戏状态机设计。
- **后端**：Python 3.11+，熟悉 FastAPI / Flask、异步调用、环境变量与密钥管理、CORS、静态资源托管。
- **围棋算法**：气计算、提子、简单劫、数子法、AI 落子候选点生成与启发式评估。
- **工程规范**：逻辑分层清晰、关键函数注释、避免全局污染、边界情况处理。

你将以「最小改动、最大复用」为原则，保留现有前端视觉风格与核心围棋规则实现，在其上叠加 AI 对弈能力。

## 二、项目背景与目标

### 2.1 现状

现有 `index.html` 是一个**本地双人对弈**围棋应用：

- 19/13/9 路可切换，Canvas 绘制木纹棋盘、立体棋子、最后一手标记。
- 已实现 `getGroup` / `countLiberties` / `removeDeadGroup` / 简单劫 / 自杀禁入 / 虚手 / 悔棋 / 历史回退 / 简易数子。
- 顶部显示当前执棋方、双方提子数、手数；右侧有棋盘规格、对局操作、对局记录面板。
- 纯前端单文件，无外部依赖。

### 2.2 目标

改造为**人与 AI 在线对弈**的围棋游戏：

1. 玩家执黑先行，AI 执白应手。
2. 对局开始前，玩家**先选择级位**（10 级 ~ 1 级），级位决定 AI 强度。
3. AI 落子由后端调用 **DeepSeek V4.1 Flash** 模型产生（模型 API Key 从**本机环境变量**读取，绝不出现在前端或代码中）。
4. 保留原有全部视觉与交互能力（悔棋、Pass、历史回退、数子结算、尺寸切换）。
5. 技术栈：**Python 3.11+ 后端 + HTML5 前端**，输出可直接运行的项目。

## 三、功能需求

### 3.1 级位选择与开局流程（新增）

- 页面加载后展示**开局设置面板**（模态框或侧栏），包含：
  - **级位选择器**：10 级、9 级、…、1 级（共 10 档），默认 10 级。
  - 可选的棋盘尺寸选择（复用现有 9/13/19）。
  - 说明文案：级位越高 AI 越强。
- 玩家点击「开始对局」后：锁定级位 → 重置棋盘 → 黑方（玩家）先行。
- 对局中可在界面上显示「当前 AI 级位」（如 `AI · 5级`）。
- 对局结束后重新开始时，保留上次选择的级位作为默认值。

### 3.2 AI 对弈（核心新增）

- **触发时机**：玩家合法落子或虚手后，若轮到白方且对局未结束，前端请求后端生成 AI 落子。
- **请求内容**：当前棋盘状态（二维数组或扁平数组）、棋盘尺寸、级位、当前手数、是否可虚手等。
- **响应内容**：AI 选择（落子坐标 `row,col` 或 `pass`）、可选的思考说明/耗时。
- **前端校验**：收到 AI 落子后，仍走本地 `game.play()` 做合法性校验（自杀/劫/占用）；若后端返回非法，前端提示并降级为「AI 虚手」或重试一次。
- **加载态**：AI 思考期间禁用落子、显示「AI 思考中…」状态与轻量 loading 动画；超时（建议 15s）给出提示并允许重试/虚手。
- **取消**：新局、悔棋、回退历史时，应取消/忽略未完成的 AI 请求（用请求序号或 AbortController 防串台）。

### 3.3 级位 → AI 强度映射（后端实现）

由后端根据级位决定模型的策略约束，建议如下（可微调并在 README 说明）：

| 级位 | AI 强度策略 |
|---|---|
| 10 级 | 高随机性：在合法点中大量随机，约 40% 概率选「较差但有气」的点，优先避免明显自损 |
| 8~9 级 | 随机为主 + 基础气/提子启发式，偶尔就近应手 |
| 6~7 级 | 启发式评分：提子 > 救活己方危险块 > 靠近上一手 > 占角/边 |
| 4~5 级 | 启发式 + 让模型在 Top-K 候选中选择，限制模型自由度 |
| 2~3 级 | 模型主导，允许较多候选点，追加规则校验与简单局面评估 |
| 1 级 | 模型主导 + 更强候选集 + 基础死活/联络启发式评分，随机性最低 |

**要求**：级位映射必须由后端实现，前端只传级位整数（1~10）。AI 逻辑需封装为独立模块（如 `ai/engine.py`），含启发式评估函数与模型调用函数。

### 3.4 沿用现有规则与交互

以下能力**必须保留且不回归**：

- 落子校验：占用点、自杀、简单劫（立即还原上一局面）非法提示。
- 提子计数、手数统计、当前执棋方展示。
- 虚手（Pass），连续两次虚手终局并弹出数子结算。
- 悔棋：人机对弈下「悔棋」应回退到**玩家上一手之前**（即撤销 AI 一手 + 玩家一手，恢复到玩家可落子的状态），并正确恢复劫争状态与 `previousBoard`。
- 历史记录点击回退到任意历史局面；回退后若轮到 AI，需重新请求 AI 落子（或回退到玩家回合为止，二选一并在 README 说明）。
- 数子结算：活子 + 单方围空，双方接触空点不计分，弹窗展示明细。
- 棋盘尺寸切换（9/13/19）后重置对局并重新开始级位流程或沿用当前级位（建议沿用当前级位直接开局）。

## 四、后端需求（Python 3.11+）

### 4.1 技术选型

- 推荐 **FastAPI + Uvicorn**（异步、自带 OpenAPI 文档、易托管静态文件）；若环境不便，可退化为 Flask，但需说明。
- 使用 `httpx`（异步）调用 DeepSeek API。
- 依赖清单写入 `requirements.txt`，版本宽松固定（如 `fastapi>=0.110`、`uvicorn[standard]>=0.29`、`httpx>=0.27`、`pydantic>=2.6`）。

### 4.2 API Key 与安全

- 模型 API Key **仅从本机环境变量读取**，变量名如 `DEEPSEEK_API_KEY`（可在 README 说明如何设置）。
- 启动时若未检测到 Key：**不崩溃**，降级为「本地启发式 AI」，并在日志与 `/api/health` 中标注 `llm: disabled`，前端开局提示「未配置模型密钥，当前为本地 AI」。
- Key 绝不写入代码、前端、日志明文；日志中如需打印仅显示掩码（如 `sk-****abcd`）。
- 后端需设置 CORS（开发期允许本地前端源），生产同源托管静态文件时可关闭宽松 CORS。
- 对模型返回做**严格 JSON 解析与合法性校验**，解析失败时回退到启发式 AI，保证接口永不 500 暴露内部细节。

### 4.3 接口设计（建议）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 返回 `{status, llm: true/false, model, version}` |
| POST | `/api/ai-move` | 请求体：`{board, size, level, moveNumber, lastMove, consecutivePasses}`；响应：`{move: {row, col} \| "pass", reason, elapsedMs, engine}` |
| GET | `/` | 托管 `index.html` 等前端静态资源 |

**请求体 `board` 约定**：`size×size` 的二维数组，`0=空、1=黑、2=白`，与前端内部表示一致（或明确转换规则并在 README 写明）。

**服务端校验**：AI 返回的落子必须经后端再校验一次（占用、自杀、劫），非法则回退启发式候选，仍非法则返回 `pass`。

### 4.4 DeepSeek V4.1 Flash 调用规范

- 模型标识以环境变量或常量配置（如 `DEEPSEEK_MODEL=deepseek-v4.1-flash`），便于替换。
- 采用 **Chat Completions 风格**调用，要求模型**只输出 JSON**，例如：
  ```json
  {"move": {"row": 3, "col": 15}, "reason": "扩展右下角"}
  ```
  或
  ```json
  {"move": "pass", "reason": "无合适落点"}
  ```
- **提示词设计要点**（后端拼装）：
  - 告知棋盘尺寸、坐标系（行/列从 0 开始，或围棋坐标 A-T 去 I），黑=1 白=2 空=0。
  - 提供当前棋盘的可读表示（如按行输出 `0 0 1 2 ...`），并说明轮白方落子。
  - 注入级位对应的策略指令（见 3.3）。
  - 要求输出严格 JSON、不要 Markdown 代码块、不要额外文字。
  - 设置 `temperature` 随级位变化（低级位更高随机性），`max_tokens` 限制。
- **候选点压缩**：为避免超长上下文，可先由启发式生成 Top-K（如 20~40）候选点，再让模型在其中选择；1~3 级可给更大 K 或全盘摘要。
- **超时与重试**：单次调用超时 12s，失败重试 1 次（指数退避），最终失败回退启发式。
- **降级策略**：网络错误 / 限流 / 解析失败 → 启发式 AI，响应中 `engine` 字段标明来源（`llm` / `heuristic`）。

## 五、前端改造要求

### 5.1 复用与改造原则

- 保留现有视觉体系（CSS 变量、木纹、棋子渐变、面板布局），**不重做 UI 风格**。
- 保留 `GoGame` 类的规则内核与 `renderBoard / renderStats / renderHistory` 等渲染函数结构；新增内容以「增量」方式接入。
- 将原「双人对弈」文案改为「人机对弈」，顶部信息区增加「AI 级位」展示。
- 原「当前执棋方」在 AI 回合显示「白方（AI）思考中…」。

### 5.2 新增/修改交互

- **开局设置面板**：级位选择（10 档，默认 10 级）+ 开始按钮；未选择级位不可开局（默认已选）。
- **AI 回合**：禁止玩家点击落子；画布 cursor 为 `wait`；状态栏显示思考提示。
- **悔棋语义**：人机模式下撤销「玩家一手 + AI 一手」，恢复到玩家回合；若历史不足则至少撤销到玩家可落子状态。
- **重新开始**：保留级位，重置棋盘，黑方先。
- **错误提示**：沿用 toast；新增 AI 请求失败、超时、未配置模型的友好提示。
- **无障碍与键盘**：保留 canvas `tabindex` 与 `aria-live` 状态文本；按钮可键盘操作。

### 5.3 前端与后端解耦

- 后端地址通过常量 `API_BASE`（默认 `''` 同源，开发可指向 `http://127.0.0.1:8000`）配置，便于本地调试。
- 所有网络请求集中到 `api.js` 风格的小模块或 IIFE 内函数（如 `requestAiMove()`），带 AbortController 与请求序号防串台。
- 前端不持有任何密钥。

## 六、代码质量与边界要求

1. **分层清晰**：规则内核 / AI 引擎 / HTTP 接口 / 前端渲染与交互 各自独立；关键函数加中文注释（气计算、提子、劫、级位映射、提示词拼装、降级）。
2. **命名语义化**，避免全局污染（前端 IIFE、后端模块化）。
3. **边界情况**：
   - 棋盘边缘、角部落子；占满棋盘时 AI 应能返回 `pass`。
   - 游戏结束后忽略落子与 AI 请求。
   - 悔棋/回退历史后，`previousBoard`（劫争）与 `consecutivePasses` 正确恢复。
   - AI 请求期间玩家点击、切尺寸、重新开始 → 取消旧请求、忽略迟到响应。
   - 模型返回非法坐标（越界、非整数、字符串坐标）→ 后端拦截回退。
   - 未配置 API Key、模型超时、返回非 JSON → 全部降级启发式并可继续对局。
4. **可配置**：棋盘尺寸常量、级位档位、模型名、超时时间、候选点 K 值均应集中配置。
5. **测试**：后端至少覆盖 4.5 中列出的用例；前端可在 README 给出手工测试清单（开局、落子、提子、劫、Pass、悔棋、AI 超时降级、数子）。

## 八、验收标准

- [ ] 开局前必须选择级位（10~1 级），开始后黑方（玩家）先落子。

- [ ] 历史回退、尺寸切换、重新开始均不出现请求串台或状态错乱。
- [ ] API Key 仅从环境变量读取；前端源码与网络请求中无任何密钥。
- [ ] 未配置 Key / 模型超时 / 返回非法 JSON 时自动降级，对局不中断。
- [ ] 视觉风格与现有页面一致，新增设置面板与级位展示融入整体设计。

## 十、约束与禁止事项

- 禁止在前端或仓库中出现真实 API Key；禁止把 Key 写进 `.env.example`。
- 禁止引入需要联网的 CDN 资源到前端（保持可离线打开的静态页面；对局时仅访问本地后端）。
- 禁止破坏现有围棋规则正确性（提子、自杀、简单劫、数子）。
- 禁止在 AI 请求失败时让对局卡死；必须有降级路径。
- 不要求实现超级劫、精确死活判定、贴目与让子；如需可列为「后续扩展」并在 README 标注。
