## 1. 总体概述

### 1.1 背景与目标

AI Fast 管理后台（ai-fast-web-admin）是平台运营管理的核心工具，负责内容审核、用户管理、数据监控和系统配置等功能。当前项目已完成脚手架搭建（路由、Store、Mock 数据），但 8 个视图组件全部缺失，后台无法运行。

本特性的目标是**实现所有视图组件，使管理后台可用**，具体包括：

- 补齐 8 个缺失的视图组件（登录、布局、仪表盘、内容管理、内容编辑、内容审核、用户管理、系统配置）
- 实现主题状态管理（亮/暗/跟随系统切换）
- 关键业务数据通过 localStorage 持久化，刷新不丢失
- 基础响应式适配，保障移动端核心操作可用

### 1.2 核心价值

- **运营可用**：补齐全部视图组件，管理员可完成登录、审核、用户管理、配置等日常操作
- **品牌一致**：采用现代管理风格，与用户端视觉语言保持统一，渐变色、圆角、卡片阴影等设计元素对齐
- **数据持久**：关键业务数据持久化至 localStorage，刷新页面后操作结果不丢失，体验接近真实系统
- **主题适配**：支持亮色/暗色/跟随系统三种主题模式，减轻长时间使用的视觉疲劳
- **移动可及**：基础响应式适配，紧急审核等场景在手机端可完成

### 1.3 技术选型与设计决策

基于 AskMe 需求访谈中已确认的 9 项决策：

| # | 决策项 | 确认方案 | 关键理由 |
|---|--------|----------|----------|
| 1 | UI 设计风格 | 现代管理风格 — 品牌色渐变、卡片阴影、圆角设计 | 与用户端品牌一致性，Element Plus CSS 变量覆盖成熟 |
| 2 | 侧边栏导航 | 可折叠侧边栏 — 默认展开，可折叠为 64px 图标模式 | 兼顾导航与空间，el-menu 原生支持折叠 |
| 3 | Dashboard 图表 | 核心指标 + 趋势图 + 分布图 | Mock 数据完整，ECharts 折线图和饼图成熟稳定 |
| 4 | 内容编辑器 | Element Plus 表单 — 纯表单方案 | 当前 description 为纯文本，后台编辑定位为结构化数据录入 |
| 5 | 数据持久化 | localStorage 手动持久化 | 可控精确，后续对接 API 时可平滑替换 |
| 6 | 内容审核交互 | 列表 + 抽屉审核 | 抽屉空间充足展示详情，保持列表可见 |
| 7 | 移动端适配 | 基础响应式 — 侧边栏变抽屉、表格横向滚动 | 紧急审核场景移动端可用，适配成本可控 |
| 8 | API 层预留 | 暂不预留 — 直接从 Store 调用 Mock 数据 | 当前核心目标是让后台可用，Store 接口设计已较规范 |
| 9 | 亮/暗色调 | 跟随系统主题 — 自动检测 + 手动切换 | 与用户端架构一致，Element Plus 原生支持暗黑模式 |

### 1.5 设计原则

- **渐进式**：当前为 Mock 阶段，优先实现功能可用，后续对接 API 时平滑替换
- **一致性**：视觉风格与用户端保持品牌统一，组件使用 Element Plus 标准交互模式
- **可维护**：Store 层已规范，视图层遵循统一的组件结构和命名规范
- **可控性**：手动实现持久化而非插件，只持久化必要的 Store 和字段

## 2. 使用场景

### 2.1 管理员登录

**角色**：管理员
**目标**：进入管理后台系统

1. 管理员访问管理后台 URL，系统展示登录页面
2. 登录页面采用品牌视觉设计，包含系统 Logo、名称和登录表单
3. 管理员输入账号和密码，点击登录按钮
4. 系统验证凭据（当前为 Mock 验证），成功后跳转至 Dashboard 页面
5. 路由守卫确保未登录用户无法访问后台页面，自动重定向至登录页

**预期结果**：管理员成功进入后台，看到数据统计仪表盘

### 2.2 数据统计总览

**角色**：管理员
**目标**：快速了解平台运营状况

1. 管理员登录后进入 Dashboard 页面，页面顶部展示 4 个统计卡片
2. 统计卡片分别显示：总用户数、总工作流数、总浏览量、总点赞数，每个卡片配有渐变色图标和今日新增数据
3. 页面中部展示 7 天趋势折线图（ECharts），包含用户增长、工作流增长、浏览量三条趋势线
4. 页面底部展示分类分布饼图（ECharts），按工作流分类展示数量占比
5. 图表配色跟随主题自动切换（亮色/暗色模式下使用不同配色方案）

**预期结果**：管理员一眼掌握平台核心运营数据和趋势

### 2.3 内容管理与编辑

**角色**：管理员
**目标**：管理工作流内容，新增或编辑工作流信息

1. 管理员点击侧边栏"内容管理"菜单，进入内容列表页面
2. 列表页以表格形式展示所有工作流，列包含标题、分类、状态、创建时间、操作按钮
3. 管理员可通过搜索框和分类/状态筛选条件快速定位目标工作流
4. 状态列使用不同颜色标签区分（已发布/待审核/已拒绝/草稿）
5. 点击"新增"按钮，进入内容编辑页面，填写标题、描述、封面、分类、标签、难度、时长等字段
6. 点击列表中的"编辑"按钮，进入内容编辑页面，表单预填已有数据
7. 编辑页面采用 Element Plus 表单，描述字段使用 textarea，标签使用 el-tag 输入
8. 点击保存后，数据更新至 Store 并持久化到 localStorage

**预期结果**：管理员可完成工作流的新增、编辑和列表管理操作

### 2.4 内容审核

**角色**：管理员
**目标**：审核待发布的工作流内容

1. 管理员点击侧边栏"内容审核"菜单，进入审核列表页面
2. 列表默认筛选展示"待审核"状态的工作流，支持切换查看全部状态
3. 每行显示工作流标题、提交者、提交时间、状态标签
4. 点击"审核"按钮，从右侧滑出抽屉面板
5. 抽屉面板展示工作流完整详情（标题、描述、封面、分类、标签、难度、时长等）
6. 抽屉底部提供"通过"和"拒绝"按钮，拒绝时需填写审核意见
7. 审核操作后，工作流状态更新，抽屉关闭，列表刷新
8. 抽屉保持列表可见，管理员可快速切换审核不同工作流

**预期结果**：管理员高效完成内容审核，审核结果即时生效且持久化

### 2.5 用户管理

**角色**：管理员
**目标**：管理平台用户账号和状态

1. 管理员点击侧边栏"用户管理"菜单，进入用户列表页面
2. 列表以表格展示用户信息：用户名、邮箱、角色、状态、注册时间、操作按钮
3. 管理员可通过搜索框查找用户，通过角色和状态筛选器过滤列表
4. 操作列提供启用/禁用切换按钮，管理员可改变用户状态
5. 用户状态变更后，Store 更新并持久化到 localStorage

**预期结果**：管理员可查看和管控平台用户状态

### 2.6 系统配置

**角色**：管理员
**目标**：维护系统运行参数和配置项

1. 管理员点击侧边栏"系统配置"菜单，进入配置页面
2. 配置项按功能分组展示（基础配置、内容配置、通知配置等）
3. 每个配置项使用合适的 Element Plus 表单组件（输入框、开关、选择器等）
4. 管理员修改配置后，点击"保存"按钮提交变更
5. 保存后配置写入 Store 并持久化到 localStorage
6. 提供"重置"按钮，恢复默认配置值

**预期结果**：管理员可维护系统配置，配置变更持久化生效

### 2.7 主题切换

**角色**：管理员
**目标**：根据个人偏好或环境光线切换界面主题

1. 管理员在 Layout 顶栏看到主题切换按钮（太阳/月亮图标）
2. 默认模式为"跟随系统"，自动检测操作系统主题偏好
3. 点击切换按钮，依次循环切换：亮色 → 暗色 → 跟随系统
4. 主题切换即时生效，影响所有 Element Plus 组件和自定义样式
5. Dashboard 图表配色跟随主题动态切换
6. 主题偏好持久化到 localStorage，下次登录自动恢复

**预期结果**：管理员可自由切换主题，偏好设置持久化

### 2.8 移动端基础使用

**角色**：管理员（手机端）
**目标**：在移动设备上完成紧急操作

1. 管理员在手机浏览器访问管理后台 URL
2. 侧边栏自动切换为抽屉模式，通过汉堡菜单按钮触发
3. 内容列表、审核列表等表格支持横向滚动查看完整数据
4. Dashboard 图表自适应宽度，保持可读性
5. 审核抽屉在移动端全屏展示，保证操作空间
6. 核心操作（审核通过/拒绝、用户启用/禁用）在移动端可正常完成

**预期结果**：移动端可完成紧急审核和管理操作，基础功能不阻塞
