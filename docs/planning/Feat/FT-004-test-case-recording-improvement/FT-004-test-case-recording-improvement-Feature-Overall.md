## 1. 总体概述

### 1.1 背景与问题

FT-003（Web Auto Tester）已实现 `/auto-test-record` 命令，基于 Playwright Codegen 提供浏览器操作录制功能，将录制结果转换为 YAML DSL 测试用例。然而，当前录制功能存在以下核心痛点：

- **单用例模式局限**：当前录制仅支持"一次录制一条用例"的模式，无法在一个浏览器会话中连续录制多条用例。每次录制新用例都需要重新启动浏览器，效率低下
- **选择器质量差**：Playwright Codegen 原始输出的选择器冗长、不稳定（如依赖 nth-child、随机 data-testid），缺少语义化优化，导致用例脆弱易断
- **缺少断言推断**：录制仅捕获操作步骤（click、fill、navigate），不推断任何断言条件，用户需手动补充断言，工作量巨大
- **步骤冗余**：录制输出包含大量冗余等待步骤、重复操作和未合并的表单填写序列，生成的用例可读性差
- **无参数化支持**：录制的硬编码数据（如账号密码、搜索关键词）无法自动提取为参数，多数据场景需手动改写
- **元数据不完整**：缺少录制时间、页面结构、视窗信息等关键元数据，影响用例的可追溯性和环境适配
- **多页面/弹窗缺失**：无法录制跨页面跳转和新窗口弹出的操作序列

### 1.2 特性目标

对 FT-003 的 `/auto-test-record` 命令进行全面改进，核心目标如下：

- **按用例逐条录制模式**：支持在同一个浏览器会话中连续录制多条测试用例，用户通过 IDE 输入 `/next` 完成当前用例并开始下一条，浏览器上下文保持不变，Codegen 重新启动
- **选择器智能优化**：自动优化选择器（缩短路径、去除不稳定属性），并在用例完成断点处提示用户确认优化结果
- **断言自动推断**：基于页面结构变化推断四种断言类型（A1 元素可见、A2 内容匹配、A4 数量断言、A6 页面结构断言），附带置信度评分
- **步骤智能优化**：自动合并连续表单填写组、智能等待替代硬等待、去重冗余等待步骤
- **可选数据参数化**：支持将硬编码数据提取为参数变量（`dataParam` 开关控制，默认关闭）
- **增强元数据**：录制时间、持续时长、页面标题、页面结构快照、实际视窗尺寸
- **多页面/弹窗支持**：支持跨页面跳转和新窗口弹出的操作录制（不含 iframe）

### 1.3 核心概念

| 概念 | 定义 |
|------|------|
| **按用例逐条录制 (Per-Case Recording)** | 在同一个持久浏览器会话中，逐条录制多条测试用例。每条用例独立保存，通过 `/next` 信号标记当前用例完成 |
| **完成断点 (Completion Breakpoint)** | 用户输入 `/next` 时触发的暂停点，此时系统执行选择器优化、断言推断、步骤合并等后处理，并提示用户确认 |
| **选择器优化 (Selector Optimization)** | 自动缩短选择器路径、去除不稳定属性（nth-child、动态 data-testid），生成语义化选择器 |
| **断言推断 (Assertion Inference)** | 基于页面 DOM 结构变化，自动推断可能的断言条件，附带置信度评分（高/中/低） |
| **步骤优化 (Step Optimization)** | 合理合并连续表单填写操作为组、用智能等待替代硬等待、去除冗余等待步骤 |
| **数据参数化 (Data Parameterization)** | 将录制中的硬编码数据（账号、关键词等）提取为 YAML DSL 的 `params` 变量 |
| **置信度评分 (Confidence Rating)** | 断言推断结果的可信程度标注，分为 高（≥80%）、中（50~80%）、低（<50%）三级 |
| **页面结构快照 (Page Structure Snapshot)** | 记录制时页面的关键 DOM 结构信息，用于断言推断和环境适配 |

### 1.4 定位与边界

**定位**：FT-004 是 FT-003（Web Auto Tester）的**增强子特性**，改进其 `/auto-test-record` 命令的录制质量和效率，不引入新命令，不改变已有命令的行为规范。

**与 FT-003 的关系**：

| 维度 | FT-003 原始录制 | FT-004 改进录制 |
|------|----------------|----------------|
| 录制模式 | 单用例，每次重开浏览器 | 按用例逐条，浏览器持久，`/next` 切换 |
| 选择器 | Codegen 原始输出 | 自动优化 + 用户确认 |
| 断言 | 无推断，需手动补充 | A1+A2+A4+A6 四类推断 + 置信度 |
| 步骤 | 原始录制，含冗余 | 合并表单组 + 智能等待 + 去重 |
| 数据 | 硬编码 | 可选参数化提取 |
| 元数据 | 基础信息 | 增强元数据（时间、页面结构等） |
| 多页面 | 不支持 | 支持跨页面/弹窗 |

**边界**：
- **仅改进录制功能**：不涉及执行引擎（`/auto-test-run`）、报告（`/auto-test-report`）、CI/CD（`/auto-test-ci`）等其他命令
- **不含 iframe**：多页面/弹窗仅支持浏览器新窗口/新标签页，不深入 iframe 内部操作
- **不含中断恢复**：录制中断恢复（如浏览器意外关闭后恢复上次进度）规划为未来特性，不在本特性范围内
- **依赖 FT-003**：本特性的所有改动均发生在 FT-003 工具集目录内，不创建新工具集

## 2. 使用场景

### 2.1 按用例逐条录制测试用例

**角色**：测试工程师

1. 用户执行 `/auto-test-record` 命令，指定目标 URL 和可选的用例标签（如 `module:login feature:auth`）
2. 系统首先扫描 `.asdm/workspace/auto-test/cases/` 目录，提示已有相似用例（避免重复录制）
3. 系统启动持久浏览器会话 + Playwright Codegen 录制器，打开目标页面
4. 用户在浏览器中执行需要测试的操作步骤（如登录流程）
5. 用户在 IDE 输入 `/next` 作为当前用例完成信号
6. 系统暂停录制，进入完成断点处理流程：
   - 提示用户输入用例名称（如 `user-login-test`）
   - 执行选择器优化、断言推断、步骤优化等后处理
   - 显示优化摘要（优化数量、推断结果、合并情况）
   - 用户确认或调整优化结果
7. 用例 YAML DSL 文件独立保存到 `.asdm/workspace/auto-test/cases/{case-name}.yaml`
8. 浏览器上下文保持不变，Codegen 重新启动，用户可继续录制下一条用例
9. 用户输入 `/end` 结束整次录制会话，关闭浏览器

**预期结果**：在同一个浏览器会话中连续录制多条测试用例，每条用例独立保存，通过 `/next` 和 `/end` 信号灵活控制录制节奏

### 2.2 选择器优化与用户确认

**角色**：测试工程师

1. 用户在录制完成后输入 `/next`，触发完成断点
2. 系统对当前用例的所有选择器执行自动优化：
   - 缩短冗长的 CSS/XPath 路径（如 `body > div:nth-child(3) > ...` → `#login-form .username`）
   - 去除不稳定属性（nth-child、动态 data-testid、随机 aria 属性）
   - 优先选择语义化选择器（id、name、aria-label、role）
3. 系统在优化摘要中列出所有优化项：原始选择器 → 优化后选择器
4. 用户逐项确认或调整优化结果（可回退到原始选择器或手动指定）
5. 确认后的选择器写入最终 YAML DSL 用例文件

**预期结果**：录制的测试用例选择器从冗长不稳定变为简洁语义化，提高用例的可维护性和跨环境兼容性

### 2.3 断言推断与置信度评估

**角色**：测试工程师

1. 用户在录制过程中执行操作（如点击"登录"按钮）
2. 系统在完成断点处，基于页面 DOM 结构变化推断断言条件：
   - **A1 元素可见**：新出现的 DOM 元素（如登录成功后出现的"欢迎"提示），置信度基于元素稳定性
   - **A2 内容匹配**：元素文本内容变化（如按钮文案从"登录"变为"已登录"），置信度基于文本确定性
   - **A4 数量断言**：列表/表格行数变化（如搜索结果数量），置信度基于数据可预测性
   - **A6 页面结构断言**：页面关键区域结构完整性（如表单字段齐全），置信度基于结构固定性
3. 每条推断断言附带置信度评分：高（≥80%）、中（50~80%）、低（<50%）
4. 系统在优化摘要中展示推断断言列表，用户可接受、修改或删除推断结果
5. 用户确认后的断言写入 YAML DSL 用例的 `assertions` 节

**预期结果**：录制生成的用例自动包含基于页面变化推断的断言条件，附带置信度评分供用户评估，大幅减少手动补充断言的工作量

### 2.4 步骤优化与合并

**角色**：测试工程师

1. 用户录制完成触发完成断点后，系统自动执行步骤优化：
   - **表单填写组合并**：将连续的 `type` 操作合并为 `form-fill-group`（如用户名+密码+邮箱连续填写合并为一个表单填写组）
   - **智能等待替代**：将 Codegen 产生的硬 `waitForTimeout` 替换为 `waitForSelector` 或 `waitForNavigation`，基于页面结构推断等待目标
   - **冗余等待去重**：去除连续重复的等待步骤（如多个 `waitForSelector` 同一目标）
2. 系统在优化摘要中展示优化统计：合并的表单组数量、替代的硬等待数量、去除的冗余等待数量
3. 用户确认优化结果

**预期结果**：录制的步骤序列从冗长杂乱变为精简有序，表单操作合并为组、等待策略智能化、冗余步骤去除，提高用例可读性和执行效率

### 2.5 数据参数化提取

**角色**：测试工程师

1. 用户在录制命令中指定 `dataParam=true` 开关（默认为 `false`，不参数化）
2. 系统在完成断点后，识别录制中的硬编码输入数据：
   - 表单填写值（如 `admin`、`password123`、`test@example.com`）
   - 搜索关键词（如 `手机`、`笔记本`）
   - 其他可变输入数据
3. 系统自动提取硬编码数据为 YAML DSL 的 `params` 变量：
   ```yaml
   params:
     username: admin
     password: password123
   steps:
     - action: type
       selector: "#username"
       value: "{{params.username}}"
   ```
4. 用户可修改参数名称和默认值

**预期结果**：开启参数化后，录制的硬编码数据自动提取为参数变量，用例可直接用于多数据场景测试，无需手动改写

### 2.6 多页面与弹窗录制

**角色**：测试工程师

1. 用户在录制过程中触发页面跳转（如点击链接导航到新页面）或新窗口弹出（如"查看详情"弹出新标签页）
2. 系统自动识别新页面/新窗口事件，在 YAML DSL 中标记 `pageTransition`：
   ```yaml
   steps:
     - action: click
       selector: "a.view-detail"
       pageTransition: new-tab  # 或 new-window / navigate
   ```
3. 系统切换录制跟踪到新页面/新窗口，继续捕获操作步骤
4. 用户可在新页面/新窗口中继续操作和录制
5. 系统在用例中记录完整的跨页面操作序列

**预期结果**：录制的用例完整记录跨页面跳转和新窗口弹出的操作序列，不再丢失多页面交互步骤

### 2.7 录制前相似用例提示

**角色**：测试工程师

1. 用户执行 `/auto-test-record` 命令，指定目标 URL 和可选标签
2. 系统扫描 `.asdm/workspace/auto-test/cases/` 目录中已有用例
3. 系统基于用例标签（`module`、`feature`）和 URL 匹配度，提示已有相似用例列表
4. 用户可查看相似用例内容，决定是否继续录制新用例或基于已有用例修改
5. 若用户选择继续录制，正常进入录制流程

**预期结果**：录制前自动提示已有相似用例，避免重复录制相同场景，提高测试资产利用率
