# FT-001 UI 设计优化 — 需求访谈追问

> 本文档记录对 FT-001 UI 设计优化特性的逐问题追问，用于澄清需求模糊点后制定最终特性规格。

**创建日期**：2026-05-26
**状态**：已完成

---

## 背景摘要

ai-fast-web-user 是 AI Agent 和工作流教学分享平台的 To C 端站点，基于 Vue3 + Element Plus + SCSS 构建。当前项目已有基础 UI 框架，包含首页、智能体广场、工作流中心、工作流详情、资源库、登录/注册、个人中心等页面，支持明暗主题切换。

### 核心价值

提升平台的视觉吸引力和用户体验，使其从"功能可用"升级为"视觉精致、交互流畅"的现代 AI 产品级界面，增强用户留存和专业感。

### 现状问题分析

通过对全量源码的审查和实际预览，识别出以下 UI 层面的问题：

| 问题域 | 现状描述 | 影响等级 |
|--------|----------|----------|
| **视觉层次** | 页面各区域视觉权重差异不大，缺少明确的视觉焦点和阅读引导 | 高 |
| **品牌一致性** | 主色 #6366f1 使用分散，渐变色、卡片样式、间距缺乏统一设计语言 | 高 |
| **首页冲击力** | Banner 区域较为平淡，缺乏 AI 产品应有的科技感和视觉冲击力 | 高 |
| **卡片设计** | WorkflowCard 和 Agent 卡片信息密度高但层次不清，视觉表现力不足 | 中 |
| **详情页体验** | WorkflowDetail 布局偏传统，缺少沉浸感和交互引导 | 中 |
| **认证页面** | 登录/注册页装饰元素简单，缺少品牌记忆点 | 中 |
| **动效系统** | 仅有 fadeInUp 基础动画，缺乏微交互和页面转场动效 | 中 |
| **暗色模式** | 部分区域对比度不足，渐变色在暗色下表现力衰减 | 低 |
| **移动端适配** | 仅有 992px/768px 两级断点，小屏幕体验粗糙 | 低 |
| **空状态处理** | 缺少空状态插图和引导，列表无数据时体验突兀 | 低 |

## 决策点

### 决策点 1：设计风格方向

**问题**：整体 UI 应该朝哪个设计风格方向优化？

**背景**：
- 当前界面偏向"功能型"设计，视觉表现力与 AI 产品定位不匹配
- 不同设计风格决定了色彩、排版、动效、布局的整体走向
- 需要平衡"科技感"与"亲和力"，避免过度设计导致用户体验负担

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **科技极简风** — 深色为主基调，大量留白+微光效，类似 Vercel/Linear 风格 | 科技感强、品牌差异化明显、暗色模式天然适配 | 亮色模式表现力受限、内容型页面阅读压力较大 |
| B | **友好渐变风** — 明亮渐变色+圆角卡片+柔和阴影，类似 Notion/Stripe 风格 | 视觉亲和力高、内容阅读舒适、亮暗模式均表现良好 | 科技感稍弱、需要精心设计避免幼稚感 |
| C | **混合平衡风** — 亮色基调+局部科技感元素（渐变光效/微动画），Header 和 Banner 区域偏科技，内容区域偏友好 | 兼顾两种风格优势、灵活度高、适应不同页面场景 | 风格统一难度较高、需要清晰的设计规范约束 |

**推荐**：✅ 选项 C — 混合平衡风

**确认理由**：
1. 作为内容分享平台，内容区域的阅读舒适度是核心需求
2. AI 产品定位需要在关键触点（Header、Banner、详情页）传递科技感
3. 混合方式最具灵活性，可通过设计规范确保整体一致性

**状态**：✅ 已确认

### 决策点 2：首页 Banner 重设计程度

**问题**：首页 Banner 应该重设计到什么程度？

**背景**：
- 当前 Banner 使用 el-carousel + 渐变背景 + 毛玻璃图标卡片，视觉冲击力不足
- Banner 是用户第一印象，直接影响跳出率和品牌认知
- 重设计范围从"微调优化"到"完全重做"不等，涉及工作量差异大

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **轻度优化** — 保留轮播结构，增强渐变色质感、优化文字排版、增加微动画 | 改动小、风险低、快速见效 | 提升幅度有限，仍偏"模板感" |
| B | **中度重设计** — 改为 Hero Section 单屏大图+动态粒子/网格背景+核心 Slogan，取代轮播 | 视觉冲击力大幅提升、现代感强、开发量适中 | 失去轮播多内容展示能力 |
| C | **重度重做** — 全屏沉浸式 Hero + 3D 动效背景（Three.js/CSS 3D）+ 滚动驱动叙事 | 极致视觉体验、品牌差异化极强 | 开发量大、性能风险、可能过度设计 |

**推荐**：✅ 选项 B — 中度重设计

**确认理由**：
1. 单屏 Hero 比 轮播 更符合现代 AI 产品首页趋势
2. 动态粒子/网格背景能传递科技感且性能可控（纯 CSS 或轻量 Canvas）
3. 核心信息（Slogan + CTA）一目了然，用户决策效率更高

**状态**：✅ 已确认

### 决策点 3：卡片组件设计升级策略

**问题**：WorkflowCard 和 Agent 卡片应该采用哪种设计升级策略？

**背景**：
- 当前 WorkflowCard 包含：封面图+难度标签+标题+描述+标签+作者+统计数据，信息密度高
- Agent 卡片包含：图标+名称+描述+标签+作者+用户数/评分，布局较平淡
- 两种卡片在视觉层次和品牌表达上都有提升空间

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **微调升级** — 保持现有布局，优化间距/圆角/阴影/色彩，增加 hover 微交互 | 改动小、一致性好 | 视觉提升有限 |
| B | **分层卡片** — 封面区（沉浸式大图）+ 内容区（白底/深底分层），hover 封面放大，内容区上浮 | 层次分明、沉浸感强、视觉表现力大幅提升 | 需要重新调校响应式布局 |
| C | **玻璃拟态卡片** — 毛玻璃背景 + 渐变边框 + 内发光，类 Apple visionOS 风格 | 视觉独特、科技感强 | 暗色模式下表现不稳定、性能消耗略高 |

**推荐**：✅ 选项 B — 分层卡片

**确认理由**：
1. 分层设计清晰区分视觉层和信息层，用户阅读效率更高
2. hover 交互增强卡片活跃感，符合内容平台的浏览习惯
3. 与推荐的设计风格方向（混合平衡风）天然契合

**状态**：✅ 已确认

### 决策点 4：详情页体验增强方向

**问题**：工作流详情页应该如何增强体验？

**背景**：
- 当前 WorkflowDetail 为传统左右布局（主内容+侧边栏），封面图 420px 固定高度
- 学习步骤使用 el-timeline 展示，交互性有限
- 缺少沉浸感和学习引导，更像"文档"而非"体验"

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **沉浸式封面** — 全宽大封面（带视差滚动）+ 渐变过渡到内容区，侧边栏 sticky | 视觉冲击力强、沉浸感好 | 视差效果在移动端需要特殊处理 |
| B | **交互式步骤** — 保持当前布局，将 timeline 升级为可交互步骤卡片（展开/折叠、进度标记） | 学习体验大幅提升、实用性强 | 视觉冲击力提升有限 |
| C | **全面升级** — 沉浸式封面 + 交互式步骤 + 浮动操作栏 + 相关推荐 | 体验最完整、最专业 | 工作量大、需逐步迭代 |

**推荐**：✅ 选项 C — 全面升级（分阶段实施）

**确认理由**：
1. 详情页是用户决策和学习的关键页面，值得重点投入
2. 可拆分为多个子任务逐步实施，首期先做沉浸式封面
3. 浮动操作栏和相关推荐对用户留存和转化有直接价值

**状态**：✅ 已确认

---

### 决策点 5：动效系统建设策略

**问题**：应该建立什么级别的动效系统？

**背景**：
- 当前仅有 `fadeInUp`、`fadeIn`、`slideInLeft`、`pulse-glow`、`float` 五个全局动画
- 页面切换有 fade 过渡，但组件级微交互几乎为零
- 现代 Web 应用的动效包含：页面转场、组件进入、hover/focus 反馈、状态切换、数据加载等

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **基础增强** — 添加 hover/focus 微交互、列表交错动画、状态切换过渡 | 改动小、性能影响极小 | 体验提升有限 |
| B | **系统级动效** — 建立完整的动效 Token（duration/easing/delay）、组件级动画规范、页面转场增强 | 体系完整、一致性好、可维护 | 需要设计和开发协同 |
| C | **高级动效** — 在 B 基础上增加 Lottie 插图动画、滚动驱动动画、手势交互 | 体验极致、品牌感极强 | 开发量大、性能风险 |

**推荐**：✅ 选项 B — 系统级动效

**确认理由**：
1. 系统级动效 Token 确保全局一致性，是可持续维护的方案
2. 中等投入获得显著体验提升，性价比最高
3. 后续可按需叠加 Lottie 等高级动效

**状态**：✅ 已确认

### 决策点 6：登录/注册页面品牌感增强

**问题**：认证页面应该做哪些品牌感增强？

**背景**：
- 当前登录/注册页为居中卡片 + 渐变圆形装饰
- 缺少品牌记忆点和情感化设计
- 认证页面是用户首次深度交互的关键触点

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **左图右表分屏** — 左侧品牌展示区（插画/3D/动态背景）+ 右侧表单 | 品牌展示空间大、现代感强 | 小屏幕需要隐藏左侧 |
| B | **沉浸式背景** — 全屏动态背景 + 毛玻璃表单卡片 | 视觉冲击力强、沉浸感好 | 品牌信息展示空间有限 |
| C | **增强现有布局** — 优化装饰元素、增加品牌 Logo + Slogan、微动画 | 改动最小、快速见效 | 提升幅度有限 |

**推荐**：✅ 选项 A — 左图右表分屏

**确认理由**：
1. 左图右表是 SaaS 产品认证页的主流模式，用户认知成本低
2. 左侧区域可承载品牌故事、产品亮点、信任背书等
3. 响应式处理成熟（移动端隐藏左侧即可）

**状态**：✅ 已确认

---

### 决策点 7：移动端体验优先级

**问题**：移动端适配应该在本次优化中占多大比重？

**背景**：
- 当前仅有 992px/768px 两级断点
- 作为内容消费平台，移动端流量占比通常较高
- 但 To C 端可能优先考虑 PC 端体验

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **PC 优先** — 本次仅优化 PC 端视觉，移动端保持可用即可 | 集中精力、交付快 | 移动端体验差距可能拉大 |
| B | **同步优化** — PC 和移动端同步进行视觉优化 | 全设备体验一致 | 工作量翻倍、可能拖慢交付 |
| C | **PC 优先 + 移动端基础保障** — PC 端重点优化，移动端确保布局不错乱+关键交互可用 | 平衡投入产出比 | 移动端视觉不会大幅提升 |

**推荐**：✅ 选项 C — PC 优先 + 移动端基础保障

**确认理由**：
1. AI 工作流内容在 PC 端的消费体验天然更好
2. 避免移动端布局错乱是底线要求，投入不多但价值大
3. 可在后续迭代中专项优化移动端

**状态**：⏳ 待确认

### 决策点 8：空状态与加载态处理

**问题**：空状态和加载态应该做到什么程度？

**背景**：
- 当前无空状态处理（列表为空时直接无内容）
- 无骨架屏（skeleton）加载态
- 这些状态虽然低频，但直接影响用户对产品完整度的感知

**选项**：

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | **基础处理** — 简单的"暂无数据"文字提示 + Element Plus 内置 skeleton | 实现简单 | 体验粗糙 |
| B | **情感化设计** — 自定义空状态插图（SVG）+ 引导文案 + 操作按钮 + 骨架屏 | 体验完整、专业感强 | 需要设计资源（插图） |
| C | **暂不处理** — 当前阶段优先处理主流程视觉 | 节省精力 | 产品完成度感知低 |

**推荐**：✅ 选项 B — 情感化设计

**确认理由**：
1. 空状态和加载态是产品"细节质感"的重要体现
2. SVG 插图可使用开源资源（如 unDraw），设计成本可控
3. 骨架屏用 CSS 即可实现，开发成本不高

**状态**：✅ 已确认
