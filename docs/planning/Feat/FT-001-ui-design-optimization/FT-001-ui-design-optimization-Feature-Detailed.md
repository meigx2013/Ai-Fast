## 1. 总体概述

### 1.1 项目背景与现状问题

ai-fast-web-user 是 AI Agent 和工作流教学分享平台的 To C 端站点，基于 Vue3 + Element Plus + SCSS 构建。当前项目已有基础 UI 框架，包含首页、智能体广场、工作流中心、工作流详情、资源库、登录/注册、个人中心等页面，支持明暗主题切换。

然而，现有界面整体偏向**功能型**设计，视觉表现力与 AI 产品定位不匹配，主要存在以下问题：

| 问题域 | 现状描述 | 影响等级 |
|--------|----------|:--------:|
| **视觉层次** | 各区域视觉权重差异不大，缺少明确的视觉焦点和阅读引导 | 高 |
| **品牌一致性** | 主色使用分散，渐变色、卡片样式、间距缺乏统一设计语言 | 高 |
| **首页冲击力** | Banner 区域较为平淡，缺乏 AI 产品应有的科技感和视觉冲击力 | 高 |
| **卡片设计** | 信息密度高但层次不清，视觉表现力不足 | 中 |
| **详情页体验** | 布局偏传统，缺少沉浸感和交互引导 | 中 |
| **认证页面** | 装饰元素简单，缺少品牌记忆点 | 中 |
| **动效系统** | 仅有 fadeInUp 等基础动画，缺乏微交互和页面转场动效 | 中 |
| **暗色模式** | 部分区域对比度不足，渐变色在暗色下表现力衰减 | 低 |
| **移动端适配** | 仅有 992px/768px 两级断点，小屏幕体验粗糙 | 低 |
| **空状态处理** | 缺少空状态插图和引导，列表无数据时体验突兀 | 低 |

### 1.2 优化目标与核心价值

本次优化的核心目标是将平台从**功能可用**升级为**视觉精致、交互流畅**的现代 AI 产品级界面，提升用户留存和专业感。

核心价值：

- **视觉升级**：通过混合平衡设计风格，在关键触点传递科技感，在内容区域保持阅读舒适度
- **品牌强化**：建立统一的设计语言和视觉规范，增强平台辨识度和专业感
- **交互提效**：建立系统级动效体系，通过微交互和页面转场提升操作流畅度感知
- **体验闭环**：补齐空状态、加载态等边缘场景，提升产品完成度感知

### 1.3 设计风格方向

已确认采用**混合平衡风**——亮色基调 + 局部科技感元素（渐变光效/微动画）。Header 和 Banner 区域偏科技感，内容区域偏友好阅读风格。

此方向的核心理念：

- 内容区域阅读舒适度是核心需求，采用明亮友好的视觉风格
- AI 产品定位在关键触点（Header、Banner、详情页）传递科技感
- 通过设计规范约束混合风格的统一性，避免视觉割裂

## 2. 使用场景

### 2.1 场景1：用户首次访问首页

**操作步骤**：

1. 用户通过浏览器访问平台首页
2. 页面加载完成，呈现全屏 Hero Section — 动态粒子/网格背景 + 核心 Slogan + CTA 按钮
3. 用户向下滚动，各板块（热门智能体、推荐工作流、资源库）以交错动画依次进入视图
4. 用户点击卡片或 CTA 按钮，跳转到对应详情页

**预期结果**：

- Hero Section 提供强烈的视觉第一印象，动态背景传递 AI 科技感
- Slogan 和 CTA 一目了然，用户能快速理解平台价值并做出行动
- 滚动过程中的动效引导阅读节奏，增强沉浸感

### 2.2 场景2：用户浏览智能体/工作流列表

**操作步骤**：

1. 用户进入智能体广场或工作流中心页面
2. 页面展示分层卡片网格 — 每张卡片包含沉浸式封面区和分层内容区
3. 用户鼠标悬停卡片，封面图放大，内容区上浮，展示微交互动效
4. 用户通过筛选/搜索缩小范围，卡片以过渡动画更新
5. 用户点击感兴趣的卡片，跳转到详情页

**预期结果**：

- 分层卡片设计清晰区分视觉层和信息层，降低信息密度压力
- Hover 微交互增强卡片活跃感，提升浏览探索欲
- 列表为空时显示情感化空状态插图 + 引导文案 + 操作按钮
- 列表加载中显示骨架屏，而非空白或突兀的内容出现

### 2.3 场景3：用户查看工作流详情

**操作步骤**：

1. 用户从列表或搜索结果点击进入工作流详情页
2. 页面顶部呈现全宽沉浸式大封面（带视差滚动效果），渐变过渡到内容区
3. 用户滚动浏览，学习步骤区域展示可交互步骤卡片（可展开/折叠、标记进度）
4. 侧边栏 sticky 展示作者信息、操作按钮（收藏/分享/开始学习）
5. 底部展示浮动操作栏和相关推荐

**预期结果**：

- 沉浸式封面提供强烈的视觉冲击力，建立对工作流的第一印象
- 可交互步骤卡片将被动阅读转化为主动探索，提升学习体验
- 浮动操作栏确保用户随时可执行关键操作，不因滚动位置而迷失
- 相关推荐引导用户继续浏览，提升平台留存

### 2.4 场景4：用户注册/登录

**操作步骤**：

1. 用户点击登录/注册入口，进入认证页面
2. 页面呈现左图右表分屏布局 — 左侧品牌展示区（动态背景/插画 + 产品亮点），右侧登录/注册表单
3. 用户在右侧表单填写信息，提交认证
4. 移动端用户看到全屏表单布局（左侧品牌区隐藏）

**预期结果**：

- 左侧品牌展示区传递平台价值和信任感，降低注册犹豫
- 右侧表单区域简洁清晰，操作流程不受视觉元素干扰
- 移动端自动适配为全屏表单，确保小屏幕操作体验

### 2.5 场景5：空状态与加载态体验

**操作步骤**：

1. 用户在某个列表页面进行筛选，结果为空
2. 页面展示自定义空状态插图（SVG）+ 引导文案 + 操作按钮（如"清除筛选"、"浏览推荐"）
3. 用户刷新页面或切换标签，数据加载期间展示骨架屏
4. 数据加载完成，骨架屏以过渡动画替换为实际内容

**预期结果**：

- 空状态不再是突兀的空白，而是有温度的引导体验
- 骨架屏降低加载等待的焦虑感，内容出现时过渡自然
- 空状态中的操作按钮提供明确的下一步行动指引

### 2.6 场景6：移动端基础浏览

**操作步骤**：

1. 用户在移动设备上访问平台
2. 页面自动适配移动端布局 — 关键内容可阅读、核心交互可用
3. 用户浏览首页、列表、详情页，布局不错乱、文字可阅读
4. 用户进行基本操作（点击、滚动、筛选），交互响应正常

**预期结果**：

- 移动端布局不出现错乱、溢出或遮挡问题
- 关键内容（卡片信息、详情内容）可正常阅读
- 核心交互（导航、筛选、点击）可正常使用
- 本次不追求移动端视觉精致度，仅保障基础可用性

## 3. 设计系统 — Design Token 与动效规范

> 代码库路径：`ai-fast-web/ai-fast-web-user/`
> 核心文件：`src/assets/main.scss`

### 3.1 设计原则

- **统一性**：所有视觉属性通过 CSS 变量（Design Token）统一管控，确保全局一致性
- **可扩展**：Token 按语义分层（基础层→语义层→组件层），支持未来扩展
- **性能优先**：动效使用 transform/opacity 属性，避免触发重排；动态效果提供降级方案
- **暗色兼容**：所有新增 Token 同时定义亮色和暗色值，确保主题切换一致性

### 3.2 Design Token 体系扩展

当前 `main.scss` 已有完整的 CSS 变量主题体系（背景色 5 级、文字色 4 级、强调色、阴影 4 级、圆角 4 级），本次需在现有体系上扩展以下 Token：

**动效 Token（新增）**：

| Token 名称 | 用途 | 亮色/暗色值 |
|------------|------|-------------|
| `--duration-fast` | 微交互（hover、focus） | 150ms |
| `--duration-normal` | 常规过渡（展开、切换） | 300ms |
| `--duration-slow` | 大幅动画（页面转场、入场） | 500ms |
| `--duration-extra-slow` | 沉浸式动画（Hero 背景） | 800ms |
| `--ease-standard` | 标准缓动 | cubic-bezier(0.4, 0, 0.2, 1) |
| `--ease-decelerate` | 减速缓动（入场） | cubic-bezier(0, 0, 0.2, 1) |
| `--ease-accelerate` | 加速缓动（退场） | cubic-bezier(0.4, 0, 1, 1) |
| `--ease-spring` | 弹性缓动（微交互） | cubic-bezier(0.34, 1.56, 0.64, 1) |

**间距与层次 Token（新增）**：

| Token 名称 | 用途 | 值 |
|------------|------|-----|
| `--spacing-hero` | Hero Section 内边距 | 80px (PC) / 40px (移动) |
| `--card-hover-lift` | 卡片 hover 上浮距离 | 8px |
| `--card-cover-scale` | 封面区 hover 缩放 | 1.05 |
| `--layer-card` | 卡片层级 z-index | 1 |
| `--layer-sticky` | Sticky 元素层级 | 10 |
| `--layer-overlay` | 遮罩层级 | 100 |
| `--layer-modal` | 弹窗层级 | 1000 |

### 3.3 动效系统设计

**动效层级架构**：

```
┌─────────────────────────────────────────┐
│  L3: 页面级动效                          │
│  - 路由转场（slide-fade / fade-scale）   │
│  - 滚动触发动画（IntersectionObserver）  │
│  - Hero 背景动效（Canvas / CSS）         │
├─────────────────────────────────────────┤
│  L2: 组件级动效                          │
│  - 卡片入场（stagger 延迟）              │
│  - 骨架屏→内容过渡                       │
│  - 空状态插图动画                        │
├─────────────────────────────────────────┤
│  L1: 微交互动效                          │
│  - hover 上浮 / 封面放大                 │
│  - 按钮按压反馈                          │
│  - 标签切换过渡                          │
└─────────────────────────────────────────┘
```

**页面转场增强**：

当前 Layout.vue 仅有 `fade` 0.25s 过渡。需新增 `slide-fade` 和 `fade-scale` 两种转场，通过 Vue `<transition>` 的 `name` 属性动态切换，基于路由 meta 信息决定转场类型。

**滚动触发动画**：

使用 `IntersectionObserver` 实现，无需引入第三方库。在 `main.scss` 中定义 `.scroll-reveal` 工具类，配合 JS 在全局注册 Observer 实例。卡片列表支持 stagger 延迟入场（通过 CSS `--stagger-delay` 自定义属性 + `transition-delay` 实现）。

### 3.4 滚动触发动画机制

**实现策略**：纯 CSS + `IntersectionObserver`，不引入第三方依赖。

**工具类设计**：

| 类名 | 效果 | 说明 |
|------|------|------|
| `.scroll-reveal` | 触发器标记 | 元素默认 opacity:0; transform:translateY(30px)，进入视口后添加 `.revealed` 类 |
| `.revealed` | 已触发状态 | opacity:1; transform:translateY(0); transition 使用 Token 变量 |
| `.scroll-reveal-left` | 从左滑入 | 初始 translateX(-30px) |
| `.scroll-reveal-scale` | 缩放淡入 | 初始 scale(0.95) |

**Stagger 延迟**：列表内子元素通过 `style="--stagger-index: N"` 设置索引，CSS 计算延迟：`transition-delay: calc(var(--stagger-index) * 80ms)`。

## 4. 组件设计 — 核心组件重构与新增

> 代码库路径：`ai-fast-web/ai-fast-web-user/src/components/`

### 4.1 分层卡片组件重设计

**当前状态**：`WorkflowCard.vue` 为传统双层结构（180px 封面 + 内容区），无分层视觉效果，hover 仅有简单 translateY(-4px)。

**目标设计**：

```
┌──────────────────────────────────┐
│         封面区（沉浸式大图）       │  ← 高度增至 220px，overflow:hidden
│     ┌──────────────────────┐     │
│     │  难度徽章 / 分类标签   │     │  ← 绝对定位在封面区上方
│     └──────────────────────┘     │
│                                  │  ← hover: 封面图 scale(1.05)，慢速过渡
└──────────────────────────────────┘
┌──────────────────────────────────┐
│         内容区（分层展示）         │  ← 白色/暗色背景，与封面区视觉分离
│  标题（2行截断）                  │
│  描述（2行截断）                  │
│  ┌────────┐ ┌────┐ ┌────┐       │
│  │ Tag1   │ │Tag2│ │Tag3│       │
│  └────────┘ └────┘ └────┘       │
│  ─────────────────────────       │  ← 分隔线
│  头像 名称     ♥ N  ⬇ N         │  ← 底部信息行
└──────────────────────────────────┘
         ↑ hover: 整体 translateY(-8px) + 内容区上浮感
```

**关键变更点**：

| 变更项 | 当前 | 目标 |
|--------|------|------|
| 封面区高度 | 180px | 220px |
| 封面区交互 | 无特殊 hover | scale(1.05) + 缓动过渡 |
| 内容区样式 | 与封面区同一卡片 | 独立背景层，分层视觉 |
| hover 上浮 | -4px | -8px + shadow 增强 |
| 分隔线 | 无 | 标签与底部信息间加分隔线 |

### 4.2 空状态组件

**当前状态**：使用 Element Plus 默认 `el-empty`，无自定义插图，无引导操作。

**目标设计**：

| 属性 | 说明 |
|------|------|
| 组件名 | `EmptyState.vue` |
| Props | `type`（类型：no-data/no-result/error）、`title`、`description`、`actionText`、`actionLink` |
| 插图 | CSS + Element Plus 图标组合实现，不依赖外部 SVG 资源 |
| 操作按钮 | 可选，点击后跳转或执行回调 |
| 动画 | 插图有轻微浮动动画（3s 周期） |

**类型与对应场景**：

| type | 图标组合 | 适用场景 |
|------|----------|----------|
| `no-data` | 文件夹 + 空白图标 | 首次进入列表，无任何数据 |
| `no-result` | 搜索图标 + 感叹号 | 搜索/筛选后无匹配结果 |
| `error` | 警告图标 + 云图标 | 数据加载失败 |

### 4.3 骨架屏组件

**当前状态**：无骨架屏实现，列表加载时直接显示数据或空白。

**目标设计**：

| 属性 | 说明 |
|------|------|

| Props | `count`（骨架卡片数量，默认 6）、`type`（card/agent/list） |
| 动画 | 从左到右的渐变扫光动画（shimmer），1.5s 循环 |
| 布局 | 与实际卡片网格布局一致，避免加载完成后的布局偏移 |

**实现策略**：基于 Element Plus `el-skeleton` 扩展，添加自定义 shimmer 动画和卡片形状模板。

### 4.4 Agent 卡片组件化

**当前状态**：Agent 卡片样式在 `Agents.vue` 和 `Home.vue` 中重复定义（内联样式），未组件化。

**目标设计**：

| 属性 | 说明 |
|------|------|
| 组件名 | `AgentCard.vue` |
| Props | `agent`（智能体数据对象） |
| 视觉升级 | 增加封面区（使用 agent.icon 放大作为视觉焦点），分层卡片风格 |
| 复用 | Home.vue 和 Agents.vue 均使用此组件 |

## 5. 页面设计方案 — 逐页详细设计

> 代码库路径：`ai-fast-web/ai-fast-web-user/src/views/`
> 调研详情参见 [FT-001-ui-design-optimization-CodeResearch-ai-fast-web-user.md](./FT-001-ui-design-optimization-CodeResearch-ai-fast-web-user.md)

### 5.1 首页 Home.vue

**当前问题**：Banner 为传统轮播（el-carousel），无 Hero Section 全屏设计，无动态背景，无滚动触发动画。

**目标方案**：

**Hero Section（替代轮播）**：

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│         [Canvas: 粒子/网格动态背景]                   │  ← 100vh 或 80vh
│                                                     │
│          ┌─────────────────────────┐                │
│          │     核心 Slogan          │                │
│          │     副标题描述           │                │
│          │  [CTA 按钮] [了解更多]    │                │
│          └─────────────────────────┘                │
│                                                     │
│          ↓ 向下滚动指示器                             │
└─────────────────────────────────────────────────────┘
```

- **动态背景**：优先使用纯 CSS 实现（多层渐变 + `@keyframes` 动画的浮动圆形），性能优于 Canvas。如需粒子效果再考虑轻量 Canvas 方案
- **滚动指示器**：底部箭头 + bounce 动画，引导用户向下浏览
- **CTA 按钮**：渐变背景 + hover glow 效果，视觉权重明显高于当前轮播按钮

**各板块升级**：

| 板块 | 当前 | 目标 |
|------|------|------|
| 热门智能体 | 静态出现 | `scroll-reveal` 交错入场，使用 `AgentCard` 组件 |
| 热点工作流 | 静态出现 | `scroll-reveal` 交错入场，使用重设计的 `WorkflowCard` |
| 平台统计 | 静态卡片 | 数字递增动画（countUp），`scroll-reveal` 触发 |

### 5.2 智能体广场 Agents.vue

**当前问题**：Agent 卡片为传统单层卡片，无封面区，`el-empty` 默认空状态，无骨架屏。

**目标方案**：

| 区域 | 变更内容 |
|------|----------|
| page-hero | 增加渐变背景装饰，提升视觉层次 |
| 分类栏 | 标签切换添加过渡动画 |
| 卡片网格 | 使用 `AgentCard` 组件，分层卡片风格，hover 微交互增强 |
| 空状态 | 使用 `EmptyState` 组件替代 `el-empty` |
| 加载态 | 使用 `CardSkeleton` 组件 |

### 5.3 工作流中心 Workflows.vue

**目标方案**：与 Agents.vue 同构升级，卡片使用重设计的 `WorkflowCard` 组件，空状态和加载态同上。

### 5.4 工作流详情 WorkflowDetail.vue

**当前问题**：封面为常规圆角卡片，无视差滚动，步骤卡片不可交互，Sidebar 无 sticky 定位，无浮动操作栏。

**目标方案**：

**沉浸式封面区**：

```
┌─────────────────────────────────────────────────┐
│              全宽大封面（视差滚动）                │  ← 宽度 100%，高度 400px
│                                                 │
│         ← 返回按钮（绝对定位，半透明背景）         │
│                                                 │
│  ─ ─ ─ ─ ─ ─ ─ ─ 渐变过渡 ─ ─ ─ ─ ─ ─ ─ ─ ─   │  ← linear-gradient 遮罩
└─────────────────────────────────────────────────┘
```

- **视差滚动**：封面区 `transform: translateY(scrollY * 0.3)` + `scale(1.1)`，通过 JS 监听 scroll 事件实现
- **渐变过渡**：底部添加 `linear-gradient(transparent, var(--bg-primary))` 实现封面到内容区的自然过渡

**可交互步骤卡片**：

| 交互能力 | 实现方式 |
|----------|----------|
| 展开/折叠 | 点击步骤标题切换内容显示，使用 Vue transition 展开动画 |
| 进度标记 | 勾选框标记已完成步骤，状态存入 localStorage |
| 视觉反馈 | 已完成步骤添加 accent 边框 + ✓ 标记 |

**Sidebar 增强**：

- 添加 `position: sticky; top: 80px`，滚动时固定
- 操作按钮组（收藏/分享/开始学习）使用渐变主按钮

**浮动操作栏**：

- 页面滚动超过封面区后显示，固定在页面底部
- 包含核心操作：开始学习、收藏、分享
- 移动端时可见性提升（因 Sidebar 隐藏）

### 5.5 登录/注册 Login.vue / Register.vue

**当前问题**：居中卡片式布局，非左图右表分屏，无品牌展示区，移动端无自适应。

**目标方案**：

```
┌──────────────────────────┬──────────────────────────┐
│                          │                          │
│    品牌展示区             │      表单区               │
│    （50%宽度）            │     （50%宽度）            │
│                          │                          │
│    ┌──────────────┐      │    Logo                   │
│    │  动态背景     │      │    标题 / 描述            │
│    │  + 产品插画   │      │    ┌──────────────┐      │
│    │              │      │    │  表单字段     │      │
│    │  产品亮点     │      │    │  ...          │      │
│    │  1. xxx      │      │    └──────────────┘      │
│    │  2. xxx      │      │    提交按钮               │
│    │  3. xxx      │      │    辅助链接               │
│    └──────────────┘      │                          │
│                          │                          │
└──────────────────────────┴──────────────────────────┘
           移动端：品牌区隐藏，表单区全屏
```

- **左侧品牌区**：渐变背景 + 浮动装饰元素（CSS 动画）+ 3 条产品亮点文字
- **右侧表单区**：简洁白色/暗色背景，与当前表单结构一致
- **响应式**：768px 以下隐藏左侧品牌区，表单区全屏展示

### 5.6 资源库 Resources.vue

**目标方案**：与列表页同构升级 — 使用分层卡片风格，`EmptyState` 替代 `el-empty`，添加 `CardSkeleton` 加载态。

### 5.7 个人中心 UserCenter.vue

**目标方案**：视觉细节优化 — 标签页切换添加过渡动画，表单卡片添加 hover 效果，整体间距和排版对齐设计规范。

### 5.8 全局布局 Layout.vue

**当前问题**：Header 无滚动行为变化，Footer 固定深色，导航无移动端汉堡菜单，页面转场单一。

**目标方案**：

| 区域 | 变更内容 |
|------|----------|
| Header | 滚动超过阈值后：缩小 padding、增加 shadow、Logo 文字隐藏仅保留图标 |
| Footer | 亮色模式下使用浅色背景，暗色模式保持深色 |
| 导航 | 768px 以下显示汉堡菜单，展开为侧边抽屉 |
| 页面转场 | 新增 `slide-fade`、`fade-scale` 两种转场，通过路由 meta 选择 |

## 6. 依赖关系

### 6.1 前置依赖

无。本特性是基础层 UI 优化，不依赖其他特性。

### 6.2 后续依赖

| 特性 | 说明 |
|------|------|
| 真实 API 接入 | 当前数据为 JSON mock，后续接入真实 API 时，本特性产出的组件需适配新数据结构 |

### 6.3 代码库依赖

| 代码库 | 路径 | 说明 |
|--------|------|------|
| ai-fast-web-user | `ai-fast-web/ai-fast-web-user/` | 唯一涉及的代码库，全部变更在此库中 |

### 6.4 第三方依赖

| 包名 | 版本 | 用途 | 是否必需 | 当前状态 |
|------|------|------|:--------:|:--------:|
| 无新增依赖 | — | 所有动效和组件通过纯 CSS + Vue 3 原生能力实现 | — | — |

> **技术决策**：不引入 animate.css、@vueuse/motion、tsparticles 等第三方依赖。动效系统基于 CSS 变量 + Vue transition + IntersectionObserver 原生实现，骨架屏基于 Element Plus el-skeleton 扩展。理由：控制包体积，减少外部依赖维护风险，项目为纯 JS 无需 TS 类型支持。
