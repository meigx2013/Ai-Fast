# Web Smoke Tester Pipeline 规范

**Document Version**: 1.0
**Last Updated**: 2026-06-09

## Overview

本文档定义冒烟测试的执行 Pipeline，即从用户输入自然语言步骤到输出测试结果的完整流程。包括步骤解析、执行策略、断言机制和异常处理。

## Pipeline 总览

```
用户输入（自然语言步骤）
    │
    ▼
[Phase 1: 解析] ──→ 结构化步骤列表 SmokeTestStep[]
    │
    ▼
[Phase 2: 上下文加载] ──→ 读取项目信息、环境配置、已有记录
    │
    ▼
[Phase 3: 执行] ──→ 逐步模拟测试人员操作，收集实际结果
    │
    ▼
[Phase 4: 断言] ──→ 对比预期与实际，判定每步 pass/fail
    │
    ▼
[Phase 5: 记录] ──→ 生成 SmokeTestRecord，持久化存储
    │
    ▼
[Phase 6: 输出] ──→ Markdown 表格格式输出测试结果
```

## Phase 1: 步骤解析

### 解析流程

1. **接收用户输入**：斜杠命令后的参数文本
2. **分词与分段**：按 `→`、`。`、`，`、序号等分隔符拆分
3. **动作识别**：识别每段的操作类型（打开、输入、点击、验证、等待等）
4. **参数提取**：提取目标元素、输入值、预期结果
5. **预期推断**：若用户未明确指定预期结果，AI 根据操作类型自动推断
6. **结构化输出**：生成 `SmokeTestStep[]`

### 操作类型映射

| 自然语言关键词 | 操作类型 (action) | 说明 |
|---------------|------------------|------|
| 打开、访问、进入 | 打开页面 | 导航到指定 URL 或页面 |
| 输入、填写、设置 | 输入文本 | 在输入框中填入文本 |
| 点击、按下、选择 | 点击元素 | 点击按钮、链接、选项 |
| 选择、切换、勾选 | 选择选项 | 下拉选择、Radio、Checkbox |
| 验证、检查、确认 | 验证结果 | 断言页面状态或内容 |
| 等待、暂停 | 等待 | 等待页面加载或异步操作完成 |
| 上传、导入 | 上传文件 | 文件上传操作 |
| 滚动、滑动 | 滚动页面 | 页面滚动到指定位置 |

### 解析示例

**输入**：`打开用户管理页面→点击新增用户→输入姓名张三→输入手机号13800138000→点击保存→验证用户列表出现张三`

**解析**：

| 步骤 | action | target | inputValue | expected |
|:----:|--------|--------|------------|----------|
| 1 | 打开页面 | 用户管理页面 | - | 用户管理页面正常显示 |
| 2 | 点击元素 | 新增用户按钮 | - | 新增用户表单弹出 |
| 3 | 输入文本 | 姓名输入框 | 张三 | 姓名字段显示"张三" |
| 4 | 输入文本 | 手机号输入框 | 13800138000 | 手机号字段显示"13800138000" |
| 5 | 点击元素 | 保存按钮 | - | 保存成功，表单关闭 |
| 6 | 验证结果 | 用户列表 | - | 列表中出现"张三" |

## Phase 2: 上下文加载

### 加载内容

执行测试前，AI 需加载以下上下文：

1. **项目信息**：从 `.asdm/contexts/` 读取项目结构、技术栈、环境配置
2. **目标系统 URL**：确定被测系统的访问地址（本地开发服务器或远程环境）
3. **已有记录**：读取 `.smoke-tester/records/` 目录，确定当天的序号起点
4. **认证信息**：如需登录，确认测试账号信息（从上下文或用户输入中获取）

### 环境检测

```
1. 检查目标系统是否可访问（尝试访问首页或健康检查端点）
2. 若不可访问 → 提示用户启动目标系统或确认 URL
3. 若可访问 → 继续执行
```

## Phase 3: 执行策略

### 执行模式

Web Smoke Tester 采用 **AI 模拟执行** 模式：

1. **代码分析执行**（推荐）：AI 阅读项目源码，分析路由、组件、API，基于代码逻辑推演操作结果
2. **浏览器执行**：如项目集成了 Playwright 等浏览器自动化工具，可启动浏览器实际操作
3. **混合模式**：先通过代码分析预判，再通过浏览器验证关键步骤

### 执行规则

1. **顺序执行**：步骤按序号依次执行，不跳步
2. **快速失败**：某步骤 fail 后，后续步骤标记为 `skip`（除非用户指定继续）
3. **超时控制**：每个步骤默认超时 30 秒，超时视为 fail
4. **截图/日志**：失败步骤尽可能收集错误信息（如网络请求、控制台错误）
5. **幂等性**：同一场景可重复执行，每次生成新的记录

### 结果收集

每个步骤执行后，AI 需收集：

- `actual`：实际观察到的结果描述
- `status`：pass / fail / skip
- `duration`：步骤耗时估算
- `errorMessage`：失败原因（仅 fail 时）

## Phase 4: 断言机制

### 断言类型

| 断言类型 | 说明 | 示例 |
|---------|------|------|
| 页面可见 | 验证目标元素/文本出现在页面上 | "首页内容正常展示" |
| 页面跳转 | 验证 URL 发生变化 | "跳转到 /dashboard" |
| 元素状态 | 验证按钮可点击、输入框可编辑等 | "登录按钮可点击" |
| 内容匹配 | 验证文本内容包含预期值 | "提示消息包含'保存成功'" |
| API 响应 | 验证接口返回状态码或数据 | "登录接口返回 200" |

### 断言判定规则

1. **明确预期**：用户在步骤中明确说明的预期结果，严格匹配
2. **推断预期**：AI 自动推断的预期结果，采用合理性判定（核心功能可用即可）
3. **冒烟级别**：冒烟测试只验证"能不能用"，不验证"好不好用"
   - ✅ 页面能打开、按钮能点击、数据能提交
   - ❌ 样式偏差、动画不流畅、非核心文案差异

## Phase 5: 记录生成

### 生成流程

1. 根据执行结果填充 `SmokeTestRecord` 各字段
2. 计算 `status`：
   - 全部 pass → `pass`
   - 有 fail → `fail`
   - 有 error → `error`
   - 全部 skip → `skip`
3. 生成 `id`：按当天日期和序号规则生成
4. 写入 `.smoke-tester/records/{id}.json`

### 持久化格式

```json
{
  "id": "STR-20260609-001",
  "scenarioName": "用户登录",
  "scenarioDescription": "打开 /login 页面，输入用户名 admin 和密码 123456，点击登录按钮",
  "steps": [
    {
      "stepIndex": 1,
      "action": "打开页面",
      "target": "/login",
      "expected": "登录页面正常加载",
      "actual": "登录页面正常加载，表单元素可见",
      "status": "pass",
      "duration": 2
    }
  ],
  "status": "pass",
  "totalSteps": 4,
  "passedSteps": 4,
  "failedSteps": 0,
  "duration": 8,
  "startTime": "2026-06-09T10:30:00+08:00",
  "endTime": "2026-06-09T10:30:08+08:00"
}
```

## Phase 6: 输出格式

遵循 [smoke-test-shared-spec.md](./smoke-test-shared-spec.md) 中定义的输出格式，以 Markdown 表格呈现测试结果。

## 异常处理

| 异常场景 | 处理策略 |
|---------|---------|
| 目标系统不可访问 | 场景标记为 `error`，提示用户启动系统 |
| 步骤执行超时 | 步骤标记为 `fail`，记录超时原因 |
| 页面元素未找到 | 步骤标记为 `fail`，记录元素选择器 |
| 前置步骤失败 | 后续步骤标记为 `skip`，说明"前置步骤失败" |
| 网络请求异常 | 步骤标记为 `error`，记录请求 URL 和状态码 |
| 存储目录不存在 | 自动创建 `.smoke-tester/records/` 目录 |

## Pipeline 执行示例

**用户输入**：
```
/smoke-test-run 打开 /login→输入用户名admin→输入密码123456→点击登录→验证跳转到/dashboard
```

**AI 执行过程**：

1. 解析为 5 个步骤
2. 加载项目上下文，确认目标系统 `http://localhost:5173` 可访问
3. 逐步执行：
   - Step 1: 访问 `/login` → 页面正常加载 → pass
   - Step 2: 在用户名框输入 `admin` → 输入成功 → pass
   - Step 3: 在密码框输入 `123456` → 输入成功 → pass
   - Step 4: 点击登录按钮 → 请求发送成功 → pass
   - Step 5: 验证跳转到 `/dashboard` → URL 变为 `/dashboard` → pass
4. 生成记录 `STR-20260609-001.json`
5. 输出 Markdown 表格结果
