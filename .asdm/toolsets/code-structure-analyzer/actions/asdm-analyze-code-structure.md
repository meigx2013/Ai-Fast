# Instructions for asdm-analyze-code-structure action

## Purpose
此指令指导 AI 模型分析 Java 代码库中单个模块的结构。接收模块名称作为参数，递归扫描模块目录，识别包结构和功能含义，生成模块的 code-structure 文件，以便后续 AI 能够了解该模块的含义并将代码写到正确的位置。

多个模块分析完毕后，使用 `asdm-merge-code-structures` action 将所有模块的 code-structure 合并为整个项目的分析报告。

## Context Injection

在执行代码结构分析之前，AI 模型应读取并理解项目上下文：

### Context Files to Read (Optional)

1. **index.md** (可选)
   - 路径：`.asdm/contexts/index.md`
   - 目的：提供工作区结构概述

**重要**：如果存在，在执行步骤之前始终读取 `.asdm/contexts/index.md`。

## Steps to Analyze Code Structure

### 1. 接收分析参数

从用户处接收以下参数：
- **路径**：要分析的代码库根目录（默认：当前目录）
- **扫描深度**：递归扫描的最大深度（可选，默认：无限制）
- **排除模式**：要从扫描中排除的模式（可选，如 `target`, `.mvn`, `.idea`, `*.class`）

### 2. 验证目标路径

验证指定的路径是否存在且可访问：
- 如果未提供路径，使用当前目录
- 检查目录是否存在且可读
- 验证它是否包含至少一个 Java 相关文件（`.java`, `pom.xml`, `build.gradle`）

### 3. 调用知识库获取上下文

在识别项目结构前，调用腾讯云代码助手 RAG 知识库获取相关技术背景：

**推荐知识库**：
- **腾讯云API** - 用于了解项目中可能集成的腾讯云服务（如 COS、TDSQL、SCF 等）的 API 规范和最佳实践

**调用方式**：
1. 在代码助手输入框中输入 `@` 或点击 `@ Add`
2. 选择 **腾讯云API** 知识库
3. 查询与项目相关的云服务信息（可选）：
   - 如果项目使用对象存储：查询 "COS API" 或 "对象存储集成"
   - 如果项目使用数据库：查询 "TDSQL" 或 "数据库连接池"
   - 如果项目使用云函数：查询 "SCF" 或 "云函数部署"
   - 如果项目使用实时音视频：查询 "实时音视频" 或 "TRTC 集成"

**知识库内容参考**：
获取的云服务规范将帮助：
- 更准确识别云服务集成模块的功能含义
- 理解云服务 SDK 的包结构和调用方式
- 推断项目中与云服务交互的代码模块职责

### 4. 识别项目结构

识别 Java 项目的类型：
- **Maven 多模块项目**：查找包含 `<modules>` 部分的父 `pom.xml`
- **Gradle 多项目**：查找 `settings.gradle` 或 `settings.gradle.kts`
- **单模块项目**：没有模块的标准 Maven 或 Gradle 项目
- **普通目录**：包含 `.java` 文件但没有构建配置的目录

### 5. 递归扫描目录结构

递归扫描目录结构：
- 创建所有目录的树结构
- 基于构建文件（`pom.xml`, `build.gradle`）识别模块边界
- 过滤掉排除的目录和文件
- 如果指定了深度限制，跟踪扫描深度

### 6. 分析每个模块

对于每个识别的模块：
- **模块标识**：名称、路径和类型
- **包结构**：列出所有 Java 包
- **源目录**：识别 `src/main/java`, `src/test/java` 等
- **模块含义**：基于包名、类名和注释分析模块的功能含义
  - 从模块名称推断功能
  - 从包名模式推断用途
  - 从类名示例了解模块内容
  - 从注释中获取额外信息

### 7. 生成模块树

生成层次化的模块树：
- **父子关系**：基于 Maven/Gradle 模块结构
- **嵌套模块**：处理深度嵌套的模块结构
- **模块元数据**：类型、路径、包数量等

### 8. 创建模块上下文文件

创建模块的 AI 上下文文件：
- **路径**：`.asdm/workspace/code-structure-analyzer/{模块名称}/code-structure.md`
- **格式**：具有清晰结构的 Markdown
- **内容**：
  1. 模块概述（模块名、路径、类型、扫描时间）
  2. 包结构列表
  3. 功能含义描述

### 9. 呈现分析摘要

向用户呈现摘要：
- 分析的总模块数
- 模块树结构概览
- 关键发现
- 生成文件的位置
- 下一步建议

## Execution Guidelines

### 何时使用此动作

在以下情况下使用此动作：
- 需要理解大型 Java 代码库的结构
- 第一次接触不熟悉的 Java 项目
- 需要在复杂的 Maven/Gradle 多模块项目中添加新功能
- 希望确保 AI 生成的代码放置在正确的模块和包中

### 分析指南

分析代码结构时：
- **尊重排除规则**：不要扫描应该排除的目录
- **深度意识**：如果指定了深度限制，请遵守
- **模块检测**：正确识别模块边界
- **含义推断**：基于名称和结构对模块功能做出合理推断
- **准确性优先**：花时间确保分析准确

### Java 特定指南

对于 Java 代码库：
- **Maven**：查找包含 `<modules>` 部分的 `pom.xml` 文件以识别多模块项目
- **Gradle**：查找 `settings.gradle` 或 `settings.gradle.kts` 以识别多项目构建
- **包命名**：Java 包通常遵循反向域名约定
- **源布局**：标准的 Maven/Gradle 源目录

## 使用方式

要使用此指令，AI 模型应：
1. 检测响应语言
2. 从用户处接收分析参数（**必须包含模块名称**）
3. 如果可用，读取项目上下文
4. 验证目标路径
5. **调用腾讯云API知识库获取云服务上下文**
6. 识别模块结构类型
7. 递归扫描目录结构
8. 分析模块的包结构
9. 创建模块上下文文件
10. 呈现分析摘要

**提示**：大型代码库应分模块分析，每个模块单独执行此 action，生成独立的 code-structure 文件。分析完所有模块后，使用 `asdm-merge-code-structures` action 合并为整体报告。

## 输出摘要

完成分析后，将生成以下文件：
- **.asdm/workspace/code-structure-analyzer/{模块名称}/code-structure.md**：模块的 AI 上下文文件，包含模块概述、包结构和功能含义描述

所有文件将保存在 `.asdm/workspace/code-structure-analyzer/{模块名称}/` 目录中。
