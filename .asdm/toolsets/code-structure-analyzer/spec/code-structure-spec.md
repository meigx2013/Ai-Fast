# 代码结构规范

## 概述

本规范定义了代码结构分析工具集生成的输出文件的结构和格式。工具集的目的是分析 Java 代码库结构，生成模块树和每个模块的功能含义描述，以便后续 AI 能够了解代码库结构并将代码写到正确位置。

## 文件：code-structure.md

主要的 AI 上下文文件，提供代码库结构的全面概述。

### 文件格式
- **位置**: `.asdm/workspace/code-structure-analyzer/{模块名称}/code-structure.md`
- **格式**: Markdown
- **编码**: UTF-8

### 文档结构

```markdown
# [模块名称] - 代码结构分析

## 模块概述
- **模块名称**: [模块名称]
- **模块类型**: [Maven 模块 | Gradle 项目 | 普通目录]
- **模块路径**: [相对于项目根的路径]
- **分析日期**: [YYYY-MM-DD HH:MM:SS]
- **源路径**: [绝对或相对路径]

## 包结构

### Java 包列表
- `com.example.module.package1`
- `com.example.module.package2`
- [更多包...]

### 包统计
- **包总数**: [数字]
- **主要包前缀**: [如 com.example.module]

## 功能含义

[基于模块名、包名、类名和结构推断此模块的功能描述]

### 主要功能
- [功能点 1]
- [功能点 2]
- [更多功能...]

### 关键类说明
[列出模块中重要的类及其用途]
```

### 内容指南

#### 模块概述部分
- 保持简洁但信息丰富
- 包含关键指标以便快速理解
- 使用项目符号提高可读性

#### 包结构部分
- 准确反映模块的实际包组织
- 列出所有找到的 Java 包
- 按包名前缀分组以提高可读性

#### 功能含义部分
- 基于模块名、包名、类名和结构推断功能
- 从以下方面推断：
  - 模块和包名称
  - 包内的类名
  - 目录结构
  - 任何可用的文档
- 列出主要功能和关键类说明

## 验证规则

### 必需内容
1. 所有输出文件必须是有效的 Markdown
2. 文件路径必须准确且一致
3. 包名称必须正确提取
4. 功能含义应基于合理推断

### 质量标准
1. 功能含义描述应该是合理的推断
2. 模块信息应该准确
3. 文档应该清晰易读

### 错误处理
1. 缺失的文件应被记录但不阻止分析
2. 不可读的文件应跳过并给出警告
3. 分析应继续进行，尽管可能有部分失败
4. 所有错误应记录在输出中
