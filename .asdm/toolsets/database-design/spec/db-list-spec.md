## Overview

本规范定义了数据库变更追踪列表（db-list.md）的结构和格式要求。此类文档用于追踪项目中所有数据库变更记录，支持版本管理和变更历史追溯。

**主要用途**:
- 追踪项目中所有数据库变更
- 记录变更版本和状态
- 支持数据库变更历史追溯
- 辅助代码评审和发布管理

## 5. 维护说明

### 5.1 添加新变更

当有新的数据库变更时：

1. 在 `变更记录` 章节添加新的变更条目
2. 填写变更的基本信息（日期、类型、范围等）
3. 更新 `概述` 章节的统计数字
4. 在 `表变更历史` 中添加/更新相应表的记录
5. 在 `版本变更记录` 中添加版本条目（如适用）

### 5.2 更新变更状态

当变更执行后：

1. 更新变更记录的 `状态` 为 `已执行`
2. 填写 `执行时间`、`执行人`、`执行环境`
3. 记录 `执行结果` 和 `影响行数`
4. 更新 `概述` 章节的统计数字

### 5.3 记录回滚

当需要回滚变更时：

1. 更新变更记录的 `状态` 为 `已回滚`
2. 填写 `回滚信息`（时间、原因、结果）
3. 在回滚脚本中记录回滚过程

## Section Guidelines

### 1. 概述

数据库变更追踪的整体情况。

**Guidelines**:
- 提供变更统计（总数、已执行、待执行、已回滚）
- 说明当前数据库版本
- 列出最后变更信息

**Example**:
```
本项目数据库变更追踪记录了系统开发过程中的所有数据库变更。
当前数据库版本为 v2.3.1，共包含 15 次变更，其中 12 次已执行、
2 次待执行、1 次已回滚。涉及表共 8 个，功能共 5 个。
```

### 2. 变更记录

所有变更的详细记录，是追踪列表的核心内容。

**Guidelines**:
- 按时间倒序排列（最新变更在前）
- 每个变更包含完整的信息
- 包含脚本文件路径
- 记录执行结果

**Important**:
- 变更 ID 应全局唯一（如 CHANGE-001、CHANGE-002）
- 状态应准确（待执行、已执行、已回滚）
- 脚本文件路径应正确

**Example**:
```markdown
### 2.1 CHANGE-015-添加会员积分表

**变更日期**: 2026-04-17
**Feature ID**: feature-002
**Feature 名称**: 会员积分系统
**变更类型**: CREATE + ALTER
**状态**: 已执行
**执行时间**: 2026-04-17 15:30:00
**版本**: v2.3.1

**变更范围**:

| 变更类型 | 数量 |
|----------|------|
| 新增表 | 2 |
| 修改表 | 1 |
| 新增字段 | 8 |

**涉及表**:

| 序号 | 表名 | 操作类型 | 说明 |
|------|------|----------|------|
| 1 | t_member_point | CREATE | 会员积分账户表 |
| 2 | t_point_flow | CREATE | 积分流水记录表 |
| 3 | t_member | ALTER | 添加积分相关字段 |

**脚本文件**:

| 脚本类型 | 文件路径 |
|----------|----------|
| DDL 变更 | scripts/feature-002/ddl_20260417153000.sql |
| 回滚脚本 | scripts/feature-002/rollback_ddl_20260417153000.sql |
| 验证脚本 | scripts/feature-002/verify_20260417153000.sql |

**执行结果**:

- 执行状态: 成功
- 执行人: zhangsan
- 执行环境: production
- 影响行数: 0
```

### 3. 表变更历史

按表维度组织的变更记录，便于查看特定表的所有变更。

**Guidelines**:
- 列出所有变更过的表
- 按变更时间排序
- 标注每项变更的类型

### 4. 版本变更记录

按版本维度组织的变更记录，支持版本追溯。

**Guidelines**:
- 与发布版本对应
- 列出该版本的所有变更
- 包含版本说明

### 5. 维护说明

如何维护追踪列表的说明。

**Guidelines**:
- 说明添加新变更的流程
- 说明更新变更状态的流程
- 说明记录回滚的方法

## Usage Guidelines

使用数据库变更追踪列表：

1. **创建**: 项目开始时创建追踪列表
2. **添加**: 每次数据库变更后添加记录
3. **更新**: 变更执行后更新状态
4. **查询**: 按需要查询变更历史
5. **追溯**: 支持问题追溯和代码评审

**Important**:
- 每次变更后及时添加记录
- 变更执行后及时更新状态
- 回滚时记录回滚信息

## Best Practices

使用本规范时：

1. **及时更新**: 每次变更后及时添加记录
2. **状态准确**: 变更执行后及时更新状态
3. **信息完整**: 记录完整的变更信息和执行结果
4. **可追溯**: 确保可以追溯每个变更的历史

### Common Pitfalls to Avoid

- **遗漏记录**: 每次变更都要添加记录
- **状态过期**: 变更执行后不及时更新状态
- **信息不全**: 缺少必要的变更信息
- **版本混乱**: 版本号不连续或重复
