# 代码概览规范 Specification

## Language Guidelines

本规范定义的文档必须使用环境中检测到的响应语言。确保所有内容遵循：

1. **语言一致性**：在整个文档中使用相同的语言
2. **写作规范**：遵循检测到语言的写作风格和格式
3. **清晰性**：确保内容清晰易懂

**支持的语言**：
- 中文 (zh)
- 英文 (en)

---

## Overview

本规范定义了代码概览报告的结构和格式要求。此类文档用于快速获取整个工作区的代码概览，结合文件分析和核心资产识别两种能力，生成一份综合性的代码库摘要报告。这份报告帮助开发者在最短时间内把握代码库的整体结构、规模和核心资产。

**主要用途**：

- 首次接触代码库，需要快速了解整体情况
- 新人入职培训，快速把握项目全貌
- 项目交接时，全面评估代码资产
- 制定重构计划前，了解代码分布

## Section Guidelines

### 元信息 (Metadata)

报告开头应包含以下元信息：

- **工作区**：工作区的名称或标识
- **分析路径**：被分析的根目录路径
- **分析时间**：报告生成的时间戳
- **语言**：检测到的响应语言

### 执行摘要

用 2-3 句话概括代码库的整体情况，包括：

- 项目类型和技术栈
- 代码规模（文件数、代码行数）
- 核心资产的主要分布

**示例**：

> 这是一个现代化的 TypeScript 项目，包含 139 个 TypeScript 文件和 134 个 JavaScript 文件，总计约 25000 行代码。项目结构清晰，采用模块化设计，核心资产主要集中在工具函数和认证模块。

### 基本统计

统计表格应包含：

- **总文件数**：所有代码文件的数量
- **总代码行数**：所有文件的代码行数总和
- **总大小**：所有文件的字节数总和（转换为 MB）
- **主要语言**：文件数最多的编程语言
- **模块数量**：功能模块的数量

### 语言分布

按编程语言统计文件分布：

- 统计每种语言的代码文件数量
- 计算各语言的代码行数
- 计算各语言的文件数占比
- 按文件数降序排列

### 目录结构

使用树形结构展示代码库目录：

- 识别主要的代码目录（如 src、lib、app 等）
- 识别配置文件目录（如 config、settings 等）
- 识别文档目录（如 docs、README 等）
- 使用 `#` 注释标注目录用途
- 排除构建产物目录

### 模块概览

按功能模块分组展示：

**每个模块包含**：

- **路径**：模块的目录路径
- **文件数**：该模块包含的代码文件数量
- **代码行数**：该模块的代码行数总和
- **功能描述**：简洁的中文功能描述

**排序规则**：

- 按代码行数降序排列
- 大型模块（>5000 行）优先展示

### 核心资产

展示引用次数最高的类和方法的 Top 5：

**高引用类表格**：

- 排名、类名、引用次数、所属模块
- 按引用次数降序排列

**高引用方法表格**：

- 排名、方法名、引用次数、所属模块
- 按引用次数降序排列

### 关键发现

基于分析结果提炼关键洞察：

**优势**：

- 代码结构的优点
- 架构设计的亮点
- 良好的编码实践

**风险点**：

- 潜在的耦合问题
- 架构风险
- 技术债务

**建议**：

- 优化建议
- 重构建议
- 后续行动项

## Usage Guidelines

生成代码概览报告时：

1. **步骤 1**：接收用户提供的分析参数
2. **步骤 2**：验证输入路径有效性
3. **步骤 3**：扫描目录结构
4. **步骤 4**：执行文件分析
5. **步骤 5**：执行核心资产分析
6. **步骤 6**：生成综合性代码概览报告
7. **步骤 7**：保存报告到指定目录

**分析深度选项**：

- **快速概览**：只分析顶层目录结构
- **标准分析**：分析所有代码文件和核心资产
- **深度分析**：包含依赖关系和架构分析

**重要提示**：

- 优先展示关键信息，细节按需展开
- 使用清晰的图表和表格
- 突出显示核心资产和关键依赖
- 提供可操作的建议

## Output Format

代码概览报告应按以下格式输出：

**格式**: Markdown
**位置**: `.asdm/workspace/code-analyzer/analysis-reports/`
**命名**: `<timestamp>-code-summary.md`

**格式详情**：

- 使用标准 Markdown 语法
- 表格使用 GitHub Flavored Markdown 格式
- 目录结构使用代码块
- 时间戳格式：`YYYYMMDD-HHMMSS`
- 代码行数可使用约数（~25000）

**示例**：

- 输出路径：`.asdm/workspace/code-analyzer/analysis-reports/20260409-101430-code-summary.md`
- 命名格式：`YYYYMMDD-HHMMSS-code-summary.md`

## Best Practices

处理代码概览时：

1. **快速定位**：优先展示关键统计信息
2. **层次分明**：从宏观到微观，从整体到细节
3. **可视化**：使用表格和树形结构增强可读性
4. **洞察提炼**：不仅仅是数据罗列，更要有分析结论

### Common Pitfalls to Avoid

- **信息过载**：不要一次性展示所有细节
- **缺乏重点**：确保核心信息突出
- **描述空洞**：避免泛泛而谈，要有具体数据支撑
- **建议模糊**：建议要具体可执行

## Checklist

生成代码概览报告前，检查：

- [ ] 报告元信息完整（工作区、路径、时间、语言）
- [ ] 执行摘要准确概括代码库整体情况
- [ ] 基本统计数据准确
- [ ] 语言分布统计正确
- [ ] 目录结构清晰且排除构建产物
- [ ] 模块概览按代码行数排序
- [ ] 核心资产 Top 5 列表完整
- [ ] 关键发现（优势、风险、建议）具有洞察力
- [ ] 报告语言一致（中文）
- [ ] 报告已保存到正确位置

- [ ] 已采用抽样分析方法
- [ ] 主要目录已优先分析
- [ ] 统计为近似值时有明确标注
