# Instructions for code-summary action

## Purpose

本指令指导 AI 模型快速获取整个工作区的代码概览，结合文件分析和核心资产识别两种能力，生成一份综合性的代码库摘要报告。这份报告帮助开发者在最短时间内把握代码库的整体结构、规模和核心资产。

## Context Injection

在执行代码概览分析之前，AI 模型应读取项目上下文：

### Context Files to Read (Optional)

1. **index.md** (推荐)
   - 路径：`.asdm/contexts/index.md`
   - 目的：了解工作区整体结构

2. **其他上下文文件** (按需)
   - 架构文档、README 文件等
   - 帮助理解项目的业务领域和技术栈

### 渐进式上下文加载策略

为避免向 AI 模型提供过多上下文，请遵循以下渐进式读取方法：

1. **初始阶段**：仅读取 `.asdm/contexts/index.md`（如果存在）
2. **按需扩展**：根据分析需要请求额外的上下文文件
3. **摘要整合**：整合所有上下文信息，形成统一的概览

## Steps to Code Summary

### 1. Receive Summary Parameters

接收用户提供的分析参数：

- **分析范围**（可选）：
  - 整个工作区（默认）
  - 指定子目录或子模块

- **分析深度**（可选）：
  - 快速概览：只分析顶层目录结构
  - 标准分析：分析所有代码文件和核心资产
  - 深度分析：包含依赖关系和架构分析

### 2. Validate Input Path

验证输入路径的有效性：

- 检查工作区根目录是否存在
- 如果指定了子目录，验证其有效性
- 确保有代码文件可供分析

### 3. Scan Directory Structure

扫描工作区的目录结构：

- 识别主要的代码目录（如 src、lib、app 等）
- 识别配置文件目录（如 config、settings 等）
- 识别文档目录（如 docs、README 等）
- 排除构建产物目录（如 node_modules、dist、build 等）

### 4. Analyze File Distribution

分析文件分布情况：

- 统计各编程语言的文件数量
- 计算各类型的代码行数
- 识别主要的模块和功能区域

### 5. Identify Top-Level Modules

识别顶层模块和组件：

- 根据目录结构识别模块划分
- 分析各模块的职责和功能
- 确定模块间的层次关系

### 6. Perform File Analysis

执行文件分析：

- 统计代码文件的数量和总行数
- 识别最大的代码文件
- 生成文件大小分布统计

### 7. Perform Core Asset Analysis

执行核心资产分析：

- 识别高引用的类和方法
- 分析核心资产的分布
- 识别关键依赖点

### 8. Generate Comprehensive Summary

### 9. Save Report

保存分析报告：

- **报告路径**：`.asdm/workspace/code-analyzer/analysis-reports/<timestamp>-code-summary.md`
- 如果目录不存在，先创建目录结构
- 确保文件保存成功

### 10. Display Summary to User

向用户展示分析结果摘要：

- 代码库的基本统计信息
- 主要模块和功能区域
- 核心资产的亮点
- 关键发现和建议

## Execution Guidelines

### When to Use This Action

在以下情况下使用此动作：

- 首次接触代码库，需要快速了解整体情况
- 新人入职培训，快速把握项目全貌
- 项目交接时，全面评估代码资产
- 制定重构计划前，了解代码分布

### Summary Generation Guidelines

生成代码概览时：

- 优先展示关键信息，细节按需展开
- 使用清晰的图表和表格
- 突出显示核心资产和关键依赖
- 提供可操作的建议

### Quality Guidelines

报告质量要求：

- 统计数据准确可靠
- 描述简洁明了
- 结构层次清晰
- 语言风格专业

## Usage

使用本指令，AI 模型应：

1. 检测响应语言（中文）
2. 接收用户提供的分析参数
3. 读取项目上下文（如有）
4. 扫描目录结构
5. 执行文件分析
6. 执行核心资产分析
7. 生成综合性代码概览报告
8. 保存报告到指定目录
9. 向用户展示关键发现

## Output Summary

完成分析后，将生成以下内容：

- **代码库概览报告**：Markdown 格式的综合报告
- **保存位置**：`.asdm/workspace/code-analyzer/analysis-reports/`

### 报告内容

报告包含：

- 执行摘要（整体情况一句话概括）
- 基本统计（文件数、行数、大小等）
- 语言分布（按编程语言统计）
- 目录结构（树形结构展示）
- 模块概览（各模块的功能描述）
- 核心资产（高引用类和方法）
- 关键发现（优势、风险、建议）

## Error Handling

### Error 1: Empty Workspace

如果工作区为空或没有代码文件：
- 提示用户确认工作区路径
- 检查是否存在被忽略的目录
- 建议创建或添加代码文件

### Error 2: Permission Issues

如果存在权限问题导致部分文件无法读取：
- 跳过无法访问的文件
- 在报告中标注被跳过的区域
- 继续分析可访问的文件

### Error 3: Large Codebase

如果代码库过大（>10000 个文件）：
- 采用抽样分析方法
- 优先分析主要目录
- 提供增量分析的选项

- [ ] 报告文件已成功创建

- [ ] 模块划分合理
- [ ] 核心资产列表完整
- [ ] 报告语言一致（中文）
