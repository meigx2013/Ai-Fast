# Instructions for file-analyze action

## Purpose

本指令指导 AI 模型对指定目录下的所有代码文件进行分析，统计每个文件的大小和代码行数，并生成简洁的中文含义描述。分析结果以 Markdown 格式输出，帮助开发者快速了解代码库结构和各模块的用途。

## Language Detection

在生成任何报告之前，必须检测并使用当前环境的响应语言：

1. **检测响应语言**：分析环境设置确定主要语言：
   - 检查系统/用户语言设置或环境配置
   - 识别项目文档和注释中使用的主要语言
   - 根据工作区上下文确定语言偏好

2. **应用语言一致性**：确保所有生成的内容使用检测到的语言：
   - 对所有 Markdown 文件、注释和文档使用相同的语言
   - 在所有生成的文件中保持语言一致性
   - 遵循检测到语言的写作规范和格式

3. **支持的语言**：
   - 中文 (zh) - 当前检测到
   - 英文 (en)

**重要提示**：语言检测是生成任何内容之前的**第一步**。所有输出在整个过程中必须一致使用检测到的语言。

## Context Injection

在执行文件分析之前，AI 模型应读取项目上下文：

### Context Files to Read (Optional)

1. **index.md** (推荐)
   - 路径：`.asdm/contexts/index.md`
   - 目的：了解工作区整体结构

2. **渐进式上下文读取** (按需)
   - 如有需要，可读取其他上下文文件
   - 例如：架构文档、技术栈说明等

### 渐进式上下文加载策略

为避免向 AI 模型提供过多上下文，请遵循以下渐进式读取方法：

1. **初始阶段**：仅读取 `.asdm/contexts/index.md`（如果存在）
2. **按需扩展**：根据需要请求额外的上下文文件

## Steps to File Analysis

### 1. Receive Analysis Parameters

接收用户提供的分析参数：

- **分析路径**（可选）：
  - 工作区根目录（默认）
  - 指定子目录或子模块路径
  - 如果用户未指定，使用当前工作区根目录

- **排除规则**（可选）：
  - 需要排除的目录（如 node_modules、dist、build 等）
  - 如果未提供，使用默认排除规则

### 2. Validate Input Path

验证输入路径的有效性：

- 检查指定路径是否存在
- 如果路径不存在，尝试使用相对路径或查找匹配目录
- 确保路径指向有效的代码目录

### 3. Scan Directory Structure

扫描目录结构并识别代码文件：

- 使用 `list_dir` 或 `search_file` 工具遍历目录
- 识别所有代码文件，支持以下扩展名：
  - JavaScript/TypeScript: `.js`, `.jsx`, `.ts`, `.tsx`
  - Python: `.py`
  - Java: `.java`
  - C#: `.cs`
  - 其他常见编程语言文件
- 排除非代码文件（如配置文件、资源文件、二进制文件等）

### 4. Analyze Each Code File

对每个识别的代码文件进行分析：

对于每个代码文件，收集以下信息：

- **文件路径**：相对于分析根目录的路径
- **文件大小**：文件占用的字节数
- **代码行数**：文件的总行数（使用 `read_file` 并计算行数）
- **文件类型**：基于扩展名识别的编程语言

### 5. Generate Chinese Description

为每个代码文件生成中文含义描述：

根据文件路径和内容生成简洁的中文描述：

- **路径分析**：解析文件路径中的目录结构和文件名
- **命名推断**：根据文件名推断文件功能
- **内容摘要**（可选）：如果文件较大，读取部分内容理解功能
- **模块归属**：确定文件属于哪个功能模块

描述格式示例：
- "用户认证模块 - 处理登录、注册和会话管理"
- "API 路由配置 - 定义 REST API 端点"
- "数据模型定义 - 用户和订单相关数据结构"

### 6. Sort and Organize Results

对分析结果进行排序和组织：

- 按文件大小降序排列（最大文件在前）
- 或按模块/功能分组
- 计算总计统计：
  - 总文件数
  - 总代码行数
  - 总文件大小
  - 各语言文件分布

### 7. Generate Markdown Report

生成 Markdown 格式的分析报告：

报告应包含以下部分：

```markdown
# 文件分析报告

**分析路径**：[路径]
**分析时间**：[时间戳]
**总计**：X 个文件，X 行代码，X KB

## 统计概览

| 指标 | 数值 |
|------|------|
| 总文件数 | X |
| 总代码行数 | X |
| 总大小 | X KB |

## 文件详情

| 文件路径 | 代码行数 | 文件大小 | 含义描述 |
|----------|----------|----------|----------|
| path/to/file1.js | 150 | 5 KB | 模块功能描述 |
| path/to/file2.ts | 200 | 8 KB | 组件功能描述 |

## 模块分布

### [模块名称]
- 文件数：X
- 代码行数：X
```

### 8. Save Report

保存分析报告到指定目录：

- **报告路径**：`.asdm/workspace/code-analyzer/analysis-reports/file-analysis/<timestamp>-file-analysis.md`
- 如果目录不存在，先创建目录结构
- 确保文件保存成功

### 9. Display Summary to User

向用户展示分析结果摘要：

- 报告保存位置
- 关键统计数据（总文件数、总行数、最大文件等）
- 提示用户查看完整报告

## Execution Guidelines

### When to Use This Action

在以下情况下使用此动作：

- 进入新的代码工作区，需要快速了解代码结构
- 新人培训时概览项目全貌
- 评估各代码文件的复杂度和规模
- 识别项目中的主要模块和职责

### Analysis Guidelines

分析代码文件时：

- 优先分析核心目录（如 src、app、lib 等）
- 跳过明显的构建产物目录（如 node_modules、dist、build）
- 对大文件（>1000 行）给予特别关注
- 描述应简洁明了，通常 1-2 句话

### Description Generation

生成文件描述时：

- 从路径和文件名推断功能
- 使用项目通用的中文术语
- 避免过于具体的实现细节
- 突出文件的主要职责

## Usage

使用本指令，AI 模型应：

1. 检测响应语言（中文）
2. 接收用户提供的分析路径参数
3. 读取项目上下文（如有）
4. 验证输入路径有效性
5. 扫描目录并识别代码文件
6. 分析每个文件的统计信息
7. 生成中文含义描述
8. 生成 Markdown 格式报告
9. 保存报告到指定目录
10. 向用户展示分析结果摘要

## Output Summary

完成分析后，将生成以下内容：

- **文件分析报告**：Markdown 格式，包含文件统计和描述
- **保存位置**：`.asdm/workspace/code-analyzer/analysis-reports/file-analysis/`

### 报告内容

报告包含：

- 分析概览（时间、路径、总计）
- 统计表格（文件数、行数、大小）
- 文件详情列表（路径、行数、大小、描述）
- 模块分布统计（可选）

### 示例输出

```
# 文件分析报告

**分析路径**：./src
**分析时间**：2026-04-09 10:14:30
**总计**：23 个文件，4521 行代码，186 KB

## 文件详情

| 文件路径 | 代码行数 | 文件大小 | 含义描述 |
|----------|----------|----------|----------|
| auth/login.js | 150 | 5 KB | 登录页面组件 |
| utils/helpers.ts | 320 | 12 KB | 工具函数集合 |
| ... | ... | ... | ... |
```

## Error Handling

### Error 1: Path Not Found

如果指定路径不存在：
- 尝试使用相对路径
- 列出可用的子目录供用户选择
- 使用工作区根目录作为默认值

### Error 2: No Code Files Found

如果目录中没有代码文件：
- 提示用户检查路径是否正确
- 列出目录中存在的文件类型
- 建议使用其他分析功能

### Error 3: Permission Denied

如果无法读取某些文件：
- 跳过无法访问的文件
- 在报告中标注被跳过的文件
- 继续分析可访问的文件

生成报告后，验证：

- [ ] 报告文件已成功创建
- [ ] 报告包含文件统计信息
- [ ] 文件描述已生成且语言一致（中文）
- [ ] 表格数据准确无误
