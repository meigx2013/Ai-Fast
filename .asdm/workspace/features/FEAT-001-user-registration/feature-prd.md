# Feature PRD: 用户注册功能

**Feature ID**: FEAT-001-user-registration
**Created Date**: 2026-05-07
**Status**: PLANNED
**Language**: zh-CN

## 1. 概述

### 1.1 功能摘要
为 AI-Fast 平台实现完整的用户注册功能，包含后端微服务（认证服务、用户服务、网关、安全公共模块）的注册相关 API 与前端注册页面对接真实后端接口。当前项目仅有前端 Mock 实现，后端服务尚未开发，需要从零构建注册流程涉及的所有微服务模块。

- **功能内容**：用户通过邮箱+密码自助注册账号，注册成功后自动登录并跳转至首页
- **必要性**：用户注册是平台的基础入口，没有注册功能则无法实现用户体系
- **受益方**：To C 端用户（可自助注册使用平台）、管理员（用户自助注册减少手动创建账号的工作量）

### 1.2 目标
- 目标 1：实现后端认证服务（ai-fast-auth）的注册 API，支持邮箱唯一性校验、密码加密存储、JWT 令牌签发
- 目标 2：实现后端用户服务（ai-fast-user）的用户创建与查询 API，支撑注册流程中的用户数据持久化
- 目标 3：实现安全公共模块（ai-fast-common-security）的 JWT 工具、密码编码器等共享组件
- 目标 4：实现网关服务（ai-fast-gateway）的路由转发与鉴权过滤器，注册接口免鉴权
- 目标 5：改造前端注册页面，从 Mock 模式切换为真实后端 API 调用，增加邮箱可用性实时校验

## 2. 用户故事

### 故事 1：新用户自助注册
**作为** 一个新访客
**我想要** 通过邮箱和密码注册账号
**以便于** 我可以登录平台浏览和收藏工作流教学内容

**验收标准**：
- 提供邮箱、用户名、密码、确认密码的注册表单
- 邮箱格式校验、密码强度校验（不少于8位）、确认密码一致性校验
- 邮箱已被注册时显示明确的错误提示
- 注册成功后自动登录并跳转到首页
- 注册失败时保留已填写的表单数据（密码除外）

### 故事 2：注册时实时校验邮箱可用性
**作为** 一个正在注册的用户
**我想要** 在输入邮箱后即时知道该邮箱是否可用
**以便于** 不必提交表单后才发现邮箱已被注册

**验收标准**：
- 邮箱输入框失焦或输入停止 500ms 后自动触发校验
- 邮箱已被注册时在输入框下方显示"该邮箱已注册"提示
- 邮箱可用时显示"邮箱可用"提示
- 校验请求频率限制，避免频繁请求

### 故事 3：管理员查看注册用户
**作为** 平台管理员
**我想要** 在管理后台查看所有注册用户的信息
**以便于** 了解用户增长情况和进行用户管理

**验收标准**：
- 可查看用户列表（邮箱、用户名、注册来源、注册时间、状态）
- 可按注册来源筛选用户（LOCAL / ADMIN_PROVISIONED / BANK_SSO）
- 可启用/禁用用户账号

## 3. 功能需求

### 需求 1：注册 API
- **ID**: REQ-001
- **描述**: 认证服务提供 `POST /auth/register` 接口，接收邮箱、密码、用户名，创建用户并返回 JWT 令牌
- **优先级**: High
- **关联故事**: 故事 1

### 需求 2：邮箱唯一性校验 API
- **ID**: REQ-002
- **描述**: 用户服务提供 `POST /user/check-email` 接口，校验邮箱是否已被注册
- **优先级**: High
- **关联故事**: 故事 2

### 需求 3：用户名可用性校验 API
- **ID**: REQ-003
- **描述**: 用户服务提供 `POST /user/check-username` 接口，校验用户名是否已被使用
- **优先级**: Medium
- **关联故事**: 故事 1

### 需求 4：密码安全存储
- **ID**: REQ-004
- **描述**: 密码使用 BCrypt 加密后存储，数据库中不保存明文密码。注册时默认 `register_source=LOCAL`、`login_page_allowed=1`、`status=1`
- **优先级**: High
- **关联故事**: 故事 1

### 需求 5：JWT 令牌签发
- **ID**: REQ-005
- **描述**: 注册成功后签发 JWT Access Token（有效期 2 小时）和 Refresh Token（有效期 7 天），Refresh Token 存储于 Redis
- **优先级**: High
- **关联故事**: 故事 1

### 需求 6：网关路由与鉴权
- **ID**: REQ-006
- **描述**: 网关配置注册相关路由（`/api/auth/register`、`/api/user/check-email`、`/api/user/check-username`）为免鉴权白名单路径，正确转发至对应微服务
- **优先级**: High
- **关联故事**: 故事 1, 故事 2

### 需求 7：前端注册页面改造
- **ID**: REQ-007
- **描述**: 改造现有 Register.vue，从 Mock 模式切换为真实 API 调用，增加邮箱实时校验、用户名校验、统一错误处理
- **优先级**: High
- **关联故事**: 故事 1, 故事 2

### 需求 8：前端 Axios 拦截器
- **ID**: REQ-008
- **描述**: 添加 Axios 请求拦截器（自动附加 JWT Authorization Header）和响应拦截器（401 处理、Token 刷新）
- **优先级**: High
- **关联故事**: 故事 1

## 4. 非功能需求

### 4.1 性能
- 注册 API 响应时间 < 500ms（P95）
- 邮箱校验 API 响应时间 < 200ms（P95）
- 支持并发注册请求（100 QPS）

### 4.2 安全
- 密码必须使用 BCrypt 加盐哈希存储，不可逆
- 注册接口需防止批量注册攻击（IP 频率限制：同一 IP 每分钟最多 5 次注册请求）
- 邮箱校验接口需防止枚举攻击（同一 IP 每分钟最多 20 次请求）
- JWT 令牌签名密钥通过 Nacos 配置中心管理，不硬编码
- 注册请求参数需进行服务端校验（SQL 注入、XSS 防护）

### 4.3 可扩展性
- 安全公共模块设计为可复用组件，供其他微服务（登录、密码重置等）复用
- 用户服务 API 模块与业务模块分层，支持 Feign 跨服务调用

### 4.4 可靠性
- 注册过程中用户服务不可用时返回明确错误信息，不产生脏数据
- 数据库操作使用事务保证一致性（用户创建与角色默认分配）

## 5. 技术需求

### 5.1 架构考量
- 微服务架构：认证服务（ai-fast-auth）负责注册入口与令牌签发，用户服务（ai-fast-user）负责用户数据持久化，通过 OpenFeign 跨服务调用
- 数据库 `users` 表已有完整字段定义（email、password、username、register_source、login_page_allowed、status），注册接口按此表结构设计
- 网关作为统一入口，所有前端请求通过网关路由到后端微服务

### 5.2 依赖
- **内部依赖**：
  - ai-fast-common-core（工具类、常量、异常定义）—— 已规划
  - ai-fast-common-redis（Redis 操作封装）—— 已规划
  - ai-fast-common-security（JWT、密码编码器）—— 需新建
- **外部依赖**：
  - Nacos（服务注册与配置中心）—— 运行时依赖
  - MySQL 8.0（users 表）—— 运行时依赖
  - Redis 7.x（Refresh Token 存储、频率限制）—— 运行时依赖

### 5.3 约束
- 后端使用 Spring Boot 3.x + Spring Cloud 2022.x + Spring Cloud Alibaba 2022.x
- ORM 使用 MyBatis-Plus 3.5.x
- 前端使用 Vue 3.x + Element Plus 2.x + Pinia 2.x
- JDK 17+、Maven 3.6+、Node.js 16+
- 数据库字符集 utf8mb4，排序规则 utf8mb4_unicode_ci

## 6. 成功标准

- 用户可通过注册页面成功注册账号，数据正确写入 `users` 表
- 注册后自动获得 JWT 令牌并登录成功
- 邮箱重复注册时返回明确的错误提示
- 邮箱实时校验功能正常工作
- 密码在数据库中以 BCrypt 哈希存储
- 注册接口可被网关正确路由且免鉴权
- 注册频率限制生效，可防止批量注册

## 8. 实现说明

- 注册流程：前端提交 → 网关转发 → 认证服务 `/auth/register` → Feign 调用用户服务创建用户 → 认证服务签发 JWT → 返回前端
- 用户表 `register_source` 字段在注册时默认设为 `LOCAL`
- 用户表 `login_page_allowed` 字段默认设为 `1`（允许密码登录）
- 用户表 `status` 字段默认设为 `1`（活跃状态）
- 前端 Pinia 用户 store 中的 `register()` 方法需要改造为调用真实 API
- 前端需要配置 Vite 开发代理，将 `/api` 请求代理到网关 `localhost:8080`
- 邮箱实时校验使用 debounce（500ms）减少请求频率

## 9. 风险与缓解

### 风险 1：后端服务从零搭建工作量较大
- **描述**: 所有后端微服务模块尚未创建，需要搭建完整的项目骨架
- **影响**: High
- **缓解**: 优先搭建公共模块（common-security）和认证服务核心逻辑，用户服务仅实现注册相关的最小 API 集合，其余接口后续迭代

### 风险 2：微服务间 Feign 调用的注册流程复杂度
- **描述**: 注册流程涉及认证服务通过 Feign 调用用户服务，分布式事务与调用失败处理需关注
- **影响**: Medium
- **缓解**: 注册流程采用同步调用+事务补偿策略，用户服务不可用时直接返回错误，不引入分布式事务框架

### 风险 3：注册安全防护
- **描述**: 注册接口可能被恶意批量调用
- **影响**: Medium
- **缓解**: 使用 Redis 实现 IP 级频率限制，后续可增加图形验证码
